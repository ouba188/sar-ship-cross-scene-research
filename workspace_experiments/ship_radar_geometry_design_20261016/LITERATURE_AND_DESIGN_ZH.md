## 结论先行

**用户于2026-10-16明确限定：所有设计服务于跨场景船型分类，不开展脱离该目标的几何、测速、尾迹或物理因素建模。** 下文是候选设计空间，不是全部实施清单，也不是已确认分类有效的组件。

当前优先回答的任务问题是：同类不同船在跨采集条件下，现有局部表示是否因证据位置/呈现变化而错配支持案例；几何关系能否在保留异类区分能力的同时改善这种匹配，并转化为完整分类净收益。这是待验证假设，不能由成像物理文献直接认定为现有错误根因。

实施前先定位实际跨场景混淆及受影响样本，复用现有端点/支持任务判断可用信息的净收益空间。随后只开发有针对性的候选。方向、运动和吃水可先作为诊断变量，不因能恢复字段或能预测属性就自动增加分支/损失；尾迹搜索与环境建模在没有任务证据前保持候选、不启动。训练以合法源端跨采集支持—查询分类为主目标，辅助任务必须说明其如何服务这一目标。

评价同时区分辅助信息学到、跨场景类别关系改善、完整系统收益；中间进展可以保留，但不能替代分类有效性结论。固定查询与支持进行配对，对照新增信息和额外容量；同场景也涨不否定其价值，不要求跨场景涨幅一定大于同场景，更不要求所有场景全胜。

值得发展的不是“给现有环带加RoPE”，而是：在船体坐标和雷达坐标中共同组织局部内容，区分船体邻近结构、可能错位的运动相关结构与环境背景，再检验这种关系表示是否改善跨采集的支持匹配和完整分类。

保留用户主张：不要求每个港口/类别/预算全胜，认可明确范围内可重复且值得成本的净收益。下文设计仍是假设，不将物理合理性当作分类提升证据，也不因已有类似研究否定方向。

## 2. 修正因素划分，不把不同物理量混为一谈

### 2.1 雷达系统与处理链

传感器、频段、模式、极化、有效分辨率、像元间距、聚焦/多视/地理编码和显示拉伸应分开记录。同一Sentinel-1系列不意味着每张图具有完全相同的采样和处理条件。对当前固定模式数据，常量无需强行做可学习输入；变化的尺度/方向用于坐标换算，处理差异用于分层解释。

像元间距不等于有效空间分辨率。GRD与SLC不能混称；GRD检测处理丢弃相位，当前PNG不支持真实相位运动补偿。官方说明：https://sentiwiki.copernicus.eu/web/s1-products

### 2.2 几何

分别定义船体长轴、船首朝向、COG、雷达地面距离向、方位向与入射角。COG是运动轨迹方向，不自动等于船首方向，尤其不能用低速COG为停泊船定义船轴。入射角与图像平面方向不是同一角度；升降轨标记不是完整的局部观测方位。

实现先将原图、地理编码和缩放关系换算到统一平面坐标，再取船轴与雷达基。船轴正反未知时处理180度歧义，不能制造船首/船尾标签。方向不确定性用于软聚合或减弱该路径，不能把缺角度记作0度。

### 2.3 船体状态、运动和水域分开

- Draught是船舶吃水，不是海底水深；AIS规范中0可表示不可用，不能当作实际零吃水。吃水可与船体状态/水动力有关，也可能携带类别捷径，需通过是否改善SAR关系学习来判断。
- AIS SOG为对地速度；COG为对地航迹方向。对水速度满足向量关系 v_ground = v_water + v_current，缺海流时不能把SOG标成真实对水速度。
- 尾迹生成关心水体相对运动和船体形状；SAR运动成像关心传感器—散射体相对运动。两者有联系，但不能用一个标量速度替代。
- 区分船体平移造成的方位向位置偏移，与时变运动/旋转造成的散焦、旁瓣变化。不能把所有细长响应解释成尾迹，也不能把所有模糊解释成航速。
- 独立考虑水域背景：近岸结构、局部纹理、风浪和可能的其他目标。当前框外掩膜不是水面分割，不能把所有框外像素称作海况。

AIS字段规范：https://www.navcen.uscg.gov/ais-class-a-reports 与 https://www.navcen.uscg.gov/ais-class-a-static-voyage-message-5 。

### 2.4 环境与传播

不必把所有环境信息判定为“无法获取”。ERA5提供风与海浪等逐时变量，可作粗粒度分析/训练侧知识；其格网尺度不能代表每艘船附近的港内状态。它也不等于大气/电离层路径误差的直接观测。当前优先局部SAR外观和可信几何；未观测环境保留为不确定性，不建立虚构的环境真值。

来源：https://www.ecmwf.int/en/forecasts/datasets/era5-hourly-data-single-levels-1940-present

## 4. 推荐核心：双坐标、观测条件化的局部关系

暂用描述名，不宣称首次提出。RoPE列为位置方案对照，不作为唯一核心。

### 4.1 输入与可用性契约

正式推断默认SAR图像加其采集元数据，不依赖实时AIS、吃水或外部环境实测；这不同于仅有PNG的严格设定。若产品几何缺失，提供图像侧版本，不能用真实外部属性悄悄补齐。

AIS长宽/吃水/速度/航向及环境重分析先用于源端诊断与可选辅助监督。只有确认SAR可预测、且主任务值得使用时再引入辅助损失。保持未见船/采集隔离，不用目标查询标签选择角度窗口。

### 4.2 内容与坐标

保留船框内局部token以及贴框、近邻、较远邻域token，不先平均成一个4维向量。浅层特征是局部内容的候选，不自动具有旋转等变性；固定物理范围内同时记录局部VV/VH数值、有效观测掩膜和位置。

对同一局部位移d，计算船轴投影u_ship = R(-theta_ship)d及雷达距离/方位投影u_radar = [e_range,e_azimuth]^T d。首先统一像元尺度与方向，再计算相对位置。保留物理尺度与相对船体尺度，避免归一化无意中抹掉长度证据；对近圆或模糊小目标降低方向置信。

用两套坐标不是增加两个骨干，而是让同一内容同时具有“沿船/横船”和“距离向/方位向”的关系描述。

### 4.3 关系计算

借鉴iRPE contextual模式，构造 r_ij = f(Delta u_ship, Delta u_radar, incidence, validity)，以 q_i^T r_ij 等内容—几何交互参与注意力。其意义是同一局部响应，在不同相对位置和观测条件下可被不同地读取。只对全部键加一个相同偏置会在softmax中抵消；统一正交旋转全部q/k也保持点积不变，均不能充当有效条件化实现。

双坐标关系网络本身不保证严格旋转不变性：普通CNN内容特征仍受方向影响。若需要严格或近似等变读出，需另比较方向通道/可转向局部编码，不能仅靠位置公式宣称达成。

### 4.4 船体邻域与运动候选的分工

船体邻域用于局部结构和环境对比；运动候选用于可能沿方位向错位的线状/拖尾结构。不预设它一定存在或一定属于目标。

第一阶段在现有可见域读取多区域与双坐标关系。只有确认视野和源端运动监督可用，第二阶段再增加沿雷达方位的细长采样带及受限可学习偏移。不得从目标SOG计算部署时不可得的精确采样位置。没有偏移真值时只称“关系搜索偏移”，不能直接命名为恢复的多普勒位移。

缺船首方向时使用轴向对称候选；有可靠方向证据才使用有向尾部候选。邻船/码头可能污染读出，必须保存其实际区域样例；不将任意方向亮线自动标为尾迹。

### 4.5 完整模型接入

用户于2026-10-16补充：设计时必须同时考虑现有管线接入，不能先开发独立模块再事后拼接。以下接口依据当前本分支实际完整读出代码核实，不把其他历史模型变体或候选组件默认算入现主线。

图像及可用几何 -> 局部内容与双坐标 -> 条件化局部关系表示 -> 同一共享编码器处理查询和支持 -> 进入现有专家核/支持残差求解 -> 原完整分类融合。

先保留原全局表征与船体路径。若继续用核求解器，使用共享向量的内积等对称构造，不给核的单侧乘查询权重。是否启用增强结果由后续查询—支持关系判断；新端点产生后必须重建源端救回/误伤监督，不能直接复用旧环带选择器参数。

#### 4.5.1 已核对的实际接口

- `E:/临时会话/prepool_local_probe_20261015/body_context_gate.py` 的 `readout` 接收 `base, expert, prior_b, prior_e, labels, q, s, relation, weights, local`；读取的分类标签只有support端，返回完整融合概率。
- `local`形状为[N,L]，是逐样本共享向量；它不是额外八分类logits。当前专家设计矩阵257列，D18项为128:256。
- 局部替换同时作用于SS与QS两块：K_new = K_old + 0.25*(16*L*L^T - D18*D18^T)。这里16是现有设计尺度，0.25是既有替换比例，不是物理常数或已证明最优值。新向量需明确范数/尺度，不能任意改变幅值等价于暗调正则强度。
- 然后与原类别关系核以0.75/0.25混合，按支持类别计数加权，以ridge=8重新求解源先验残差。基础路独立适配，最终为0.5*(softmax(base_score)+softmax(expert_score))，不是对两个原始分数直接平均。
- `run_body_context.py` 的 `predict` 已调用这个可微读出；其训练损失来自完整融合后的查询概率。当前有结构上的梯度通路，尚未实现/验证本次几何编码器训练。
- `full_readout.py::infer_with_local` 提供对应NumPy读出，用于冻结参数后的执行与配对比较。新设计需要与该完整读出一致，不仅在孤立检索器中验证。

#### 4.5.2 新模块替换什么，不替换什么

主候选输出是保留船体直通信息的几何条件化局部向量L_theta，替换当前body/ring局部表示的构造。不额外开第三个分类器，不丢弃原全局基础/专家证据，不重启5%交接。初轮冻结原先验、类别关系映射/权重与融合比例，使收益可以定位到局部证据组织。

输入接口除局部token与坐标外，必须包含同样本ID对应的几何有效性/方向置信和区域可见性；不能从4维统计恢复空间结构，故需要新增合法源端及目标支持/查询的局部特征缓存。冻结骨干时可缓存浅层特征，只训练读取器；如冻结内容限制了效果，再依据证据决定是否局部微调，而不是一开始重训全部。

#### 4.5.3 训练与推断一致

源端训练按实际目标的支持预算与场景组织构建跨采集任务：L_theta同时处理support与query -> 同时生成SS/QS -> 重新求解支持系数 -> 完整融合概率 -> 源查询分类损失。梯度穿过关系构造和线性求解更新读取器，不复用旧系数、不对关键中间结果detach。实际预算可变，不将64写死。

目标推断冻结theta及源端拟合的变换，仅用允许的目标支持标签重新求解系数；查询标签只用于事后评价。基础路未改变时，其适配结果可以在相同支持任务下复用。已有源先验和类别关系核第一阶段保持冻结，不需要因局部向量改变而无条件全量重训。

如随后接入QSRG，源端重算“保留船体”与“使用新邻域”的两种完整端点和关系特征，再训练/选择门控。先确认新表示有任务净收益，再测试门控附加效用；不把旧门控收益直接算到新模块。预测开销包括局部读取、专家重求解以及若启用门控的双端点评估，不宣称因此省算力。

#### 4.5.4 判定接入是否成功

除完整跨场景净收益外，针对实际接入风险检查：同一support/query身份与标签使用边界；SS/QS同步更新；表示尺度匹配；旧local输入的读出复现；新模块梯度可达。检查失败时分别修正样本对齐、核构造、尺度或梯度链，不将其直接归为研究方向无效。仅结构连通或辅助指标改善不等于有效组件已完成。

## 5. 有辨别力而不过度堆叠的验证

先做信息可用性与价值判断，再训练正式模块。当前已有邻域净收益，只支持邻域候选，不自动支持角度、尾迹或吃水候选。

1. 在合法源端确认方向质量、字段缺失、实际米制视野和可用跨采集支持任务。不将缺字段样本全部静默删除，避免改变任务人口。
2. 保持相同局部内容/区域/支持查询，比较图像坐标、船轴坐标、船轴+雷达双坐标；固定骨干和可比源端调参机会。
3. 强对照是“角度直接输入”和“角度控制局部关系”，回答收益是否只是额外属性分类，而不是位置结构的作用。
4. 对内容固定的角度关系进行源端预设的小扰动，结合不同方向置信、速度/偏移与区域截断分层；扰动用于判断模型依赖，不是制造真实物理观测。不要将任意图像旋转等同于重新从另一方向成像。
5. 只在第二阶段引入偏移走廊：和相同像素范围、相同token预算的无方向/固定读取比较。扩视野与新编码的增益分开，否则不能归因。
6. 评价分三层：几何/条件辅助任务是否学到；跨采集不同船的类别关系/支持核是否更有用；完整OA/BA、连续风险、救回/误伤及成本是否受益。支持抽样重复不是独立训练种子。

若几何关系提升而分类未提升，检查支持核/读出与目标是否匹配；若只在方向准确且证据未截断时受益，保留该范围并改进可靠性，不作一票否决。若只依赖源场景身份且不能迁移，则修正训练组织或收缩主张，不无限增加模块。

## 6. 候选贡献表述

“针对中低分辨率SAR中船体及邻域证据受观测几何与运动成像共同影响的问题，研究船体坐标与雷达坐标联合的条件化局部关系表示。在保留船体基本判别证据的同时，对具有不同位置语义和可见性的邻域信息进行选择性读取，并通过少量目标支持案例验证其跨采集分类价值。”

这与普通旋转对齐的区别在于保留雷达观测差异，与直接属性融合的区别在于改变内容—位置关系，与尾迹测速的区别在于优化支持分类效用。这些是待证实的贡献方向，不是已实现或已验证首创。
