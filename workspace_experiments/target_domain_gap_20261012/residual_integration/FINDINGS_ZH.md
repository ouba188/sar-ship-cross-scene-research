# 校正与融合接入：正信号、类别代价与选择失配

日期：2026-10-12。本轮完成。仅修改侧线本目录；主线程实验、权重与论文未改动。

## 一句话结论

**不是没有可利用的信息，而是当前更新在重要混淆类别之间产生了过于同向的边界移动；保留更新有局部收益，但源港选择接法未转化为目标任务的净提升。**

公开集一个预先固定的接法获得OA +0.212、BA +0.054个百分点，值得保留；不能把它冒充源端选中的方案。该均值也掩盖了集装箱船召回率约+12.05、散货船约-12.13个百分点的明显交换。下一步应先验证能否用同一64例选择合适接法、约束类别间误伤，不是直接增加新特征模块。

## 1. 做了什么

沿用上轮source_fixed的64标签专家先验更新D，冻结基础分支、双骨干特征、支持核、核岭强度8和最终等权概率融合。比较四种接法：

| 接法 | 专家分数 | 含义 |
| --- | --- | --- |
| original | P+R | 原先验与原支持残差 |
| resolve | P+D+R_new | 先更新先验，再重算支持残差；上一轮接法 |
| retain_half | P+R+0.5D | 保留旧残差，叠加半强度更新 |
| retain_full | P+R+D | 保留旧残差，叠加全强度更新 |

共77个既有源港留出任务；随后三个港口与OpenSARShip 2.0各5组64支持，共20组目标评估。四臂、强度与选择规则都在目标评价前固定。无神经网络训练、无新标签。

按任务分别在源端选接法，目标为港口等权完整模型OA，同时要求平均BA不低于原模型。不要求每港/每类/每次都赢，也不设显著性门槛。原模型仍是合法候选。

公开集采用已有更强的matched post-tail source-head基线，OA/BA=42.5971/34.6744，不退回较弱历史版本。

| --- | --- | ---: | ---: | ---: | ---: |
| 洛杉矶 | resolve | +0.0617 | +0.1740 | 0.0000 | -0.2812 |
| 巴生港 | retain_full | +0.2752 | +0.1116 | -0.0893 | -0.1086 |

| OpenSARShip 2.0 | original | 0 | 0 | 0 | 0 |

因此，这轮不能交付一个已验证更优的源端选择器。尤其巴生港：即使源端留一港重选19次都选择retain_full，目标结果仍略降。这说明源端选择稳定，不等于选择依据能迁移到目标。

源端留一港选择重放的OA/BA均值增量依次为：洛杉矶+0.0411/-0.0015，巴生港+0.2752/+0.1116，桑托斯-0.0100/-0.0463，公开集对应源任务-0.0412/-0.0190。它是内部开发诊断，不是独立确认。

## 3. 所有预定接法：存在局部正收益

以下不按目标结果改选主方案，只记录预定机制对照。每格为完整模型OA/BA增量，单位百分点。

| 任务 | resolve | retain_half | retain_full |
| --- | ---: | ---: | ---: |
| 洛杉矶 | 0.000 / -0.281 | +0.193 / +0.041 | +0.154 / -0.045 |
| 巴生港 | +0.012 / -0.091 | -0.048 / -0.067 | -0.089 / -0.109 |
| 桑托斯 | +0.100 / +0.002 | -0.063 / -0.013 | -0.063 / -0.014 |
| OpenSARShip 2.0 | -0.049 / -0.087 | +0.109 / -0.036 | +0.212 / +0.054 |

公开集retain_full的完整OA/BA为42.8090/34.7283。固定公共查询交集后，仍有+0.2442/+0.0291个百分点；洛杉矶retain_half公共查询为+0.1887/+0.0532。小正信号不能因未在所有任务获胜而删掉，也不能忽略其边界。

### 公开集支持抽样敏感性

retain_full在五组支持中OA、BA均为3组正、2组负。配对增量标准差分别0.7183、0.7024个百分点。五组OA增量为：-0.0543、+0.3260、+0.3260、-0.7607、+1.2225；BA为-0.5326、-0.6364、+0.1118、+0.2123、+1.1144。

移除收益最大的那一组后，其余四组平均OA/BA=-0.0408/-0.2112。该检查不是要求每组都赢，而是说明目前正均值对支持抽样敏感。五组查询重叠，不能把这些数字当成独立数据集置信界，也不能未经证据把负增量排除为随机噪声。

概率损失更一致：retain_full完整融合NLL平均下降0.016365，Brier下降0.006146，五组均改善。这是概率预测风险改善，不等同于已证明校准改善或top1稳定获益。

## 4. 为什么这次最终能小涨，但专家自己反而略降

公开集各阶段相对该阶段原参照的增量：

| 阶段 | resolve OA/BA | retain_full OA/BA |
| --- | ---: | ---: |
| 专家先验 | +3.0698 / +1.4318 | +3.0698 / +1.4318 |
| 加支持校正的专家 | +0.2391 / +0.1502 | -0.1087 / -0.1593 |
| 完整等权概率融合 | -0.0489 / -0.0868 | +0.2119 / +0.0539 |

**保留全部先验变化，不等于保留全部先验准确率收益。** 支持残差原本已有作用；不重算它会改变组合的意义，并可能重复使用同一支持证据。这一对照不支持“只要去掉抵消，专家就更准”。

然而最终融合不仅使用专家第一名，还使用完整类别概率。固定基础分支后，retain_full最终OA/BA变化可精确拆分为：

| 样本组 | OA贡献/百分点 | BA贡献/百分点 | 每组平均救回/误伤 |
| --- | ---: | ---: | ---: |
| 专家首选类别没变 | +0.3477 | +0.0910 | 70.2 / 57.4 |
| 专家首选类别变了 | -0.1358 | -0.0371 | 71.0 / 76.0 |
| 合计 | +0.2119 | +0.0539 | 141.2 / 133.4 |

因此这个局部净收益主要来自专家概率变化与基础分支共同改变融合边界，而非专家自身多改对了样本。专家单独每组救回159.2、误伤163.2；最终融合救回141.2、误伤133.4。这些是当前协议的决策路径解释，不是物理因果分离。

## 5. 主要在改变什么边界：散货船与集装箱船

公开集retain_full，最终模型逐类召回增量，单位百分点：

| 船型 | 平均查询数/组 | 召回增量 | 平均救回 | 平均误伤 |
| --- | ---: | ---: | ---: | ---: |
| 散货船 | 854.2 | -12.1251 | 0.2 | 103.8 |
| 渔船 | 481.0 | -0.2869 | 3.4 | 4.8 |
| 杂货船 | 311.0 | -2.8907 | 1.2 | 10.2 |
| 成品油/化学品船 | 803.4 | +0.2768 | 14.6 | 12.4 |
| 集装箱船 | 956.6 | +12.0504 | 116.2 | 1.0 |
| 原油船 | 146.2 | +2.7624 | 5.0 | 1.0 |
| 拖轮 | 74.8 | +0.2740 | 0.2 | 0.0 |
| 海工补给船 | 53.8 | +0.3701 | 0.4 | 0.2 |

五组累计的主要变动包括：原误判为散货船的集装箱船救回413次；原正确散货船被改判集装箱船367次。这是跨draw累计事件数，不能称为780艘不同船。

进一步直接检查分数方向，而非只看混淆表：

| 真实类别 | 先验“集装箱-散货”分数差平均增量 | 分数向集装箱方向移动的比例 | 最终概率差向集装箱移动的比例 |
| --- | ---: | ---: | ---: |
| 散货船 | +0.3432 | 98.78% | 98.85% |
| 集装箱船 | +0.4151 | 98.81% | 98.89% |

两类都几乎统一向集装箱方向移动：这解释了为何能纠正原来漏判的集装箱船，也同时误伤散货船。更新量并非常数，不能说它纯粹只有截距变化；但在这对类别上，它明显缺少“该救集装箱、该保散货”的选择性。

已确定的是计算作用路径和类别收益交换。尚未分清这份同向偏移中，支持案例代表性、类别一阶统计估计与特征可分性分别贡献多少；不将其包装为已解释真实散射机制。

## 6. 检查与边界

- 独立加权RidgeClassifier验证64例source-fixed头更新；核残差抵消恒等式、支持排列不变与零更新保持原模型测试通过。
- 原三个港口源端专家分数复现通过。公开集发现FP32拟合与FP64重算最大约0.000189的分数差；独立FP64拟合与统计量解只差2.8e-13。源端先验改为锚定原FP32路径，更新用FP64新旧头之差，未将数值重算当成收益。
- 四个目标任务的original和resolve逐概率复现上一轮保存结果；基础分支概率在所有臂一致。
- 历史pickle记录sklearn 1.8.0，当前环境1.7.2，会有版本警告；本轮依赖的分数/概率路径已经上述复现检查，没有更改全局环境。
- 仍为原完整模型行级查询排除协议，存在支持/查询同船重叠；不能写成严格未见船确认。源港任务复用表征，内层留港不等于骨干从未见过该港。开发数据已多轮使用。
- 本轮没有目标结果驱动的参数扩展，没有新增交接预算实验或新骨干对照。

## 7. 下一步建议：先检查64例能否提供选择依据

不将当前选择器并入主模型，也不删除局部正结果。下一轮最紧凑的验证应是：在同一64个支持案例内部做分组交叉验证，比较这四个已冻结接法，再用全部64例重拟合，查询只作最终评价。

同时重点核对散货/集装箱的救回与误伤，判断支持内部证据能否识别何时适合推动该边界。先验证这个选择信号是否可用，再决定是否开发类别对条件校正；不能因为已经找到一对混淆类别就马上堆出模块。

这一步保持64标签预算，不要求部署知道查询标签。但支持集小、类别覆盖有限，内部选择仍可能不可靠，需要实际验证，不能提前保证收益。
