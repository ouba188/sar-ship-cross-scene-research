# 当前论文实验补全方案

日期：2026-11-09。执行更新：核心五配置×三种子的新共同起点联合训练及当前工作版OSS1冻结外推已完成，详见ROUND_FINDINGS_ZH.md。原计划中的分阶段训练日程尚未完整重放；本轮联合优化是明确记录的实施变体，不替代该缺口。以下保留总体方案，不把未完成事项写成已完成。

## 一、最需要补的不是更多案例，而是三种定量证据

1. **系统是否值得使用：** 同样数据、训练资源和输入信息下，当前完整模型相对普通骨干、合理注意力基线和简单参考聚合，有多少收益、增加多少成本？
2. **三个模块分别做了什么：** 从共同初始化配套训练，移除或替换一个模块，其他条件保持一致。区分“模块有帮助”和“内部特定设计有帮助”。
3. **结论覆盖多大：** 当前版本在公开和自建数据的跨场景协议下是否保持一定净收益？不要求各类、各场景全部获胜。

救回案例用于解释已经测得的收益，不能替代完整预测集的定量统计。已有历史负结果保留在研究档案，不需要把全部开发过程写成正文。

## 三、第一优先：OSS2统一组件消融

先跑五个核心配置，每组3个配对种子；再用三个单模块配置补齐完整八组合。八组合总计24次训练，不是已有旧检查点的测试时开关。

| 配置 | CRFB | RGRP | RCEW | 回答的问题 | 顺序 |
|---|---|---|---|---|---|
| Plain | 无 | 无 | 无 | 普通共享骨干的起点 | 首批 |

| No-CRFB | 无 | 有 | 有 | M1增量 | 首批 |

| RGRP-only | 无 | 有 | 无 | M2单独是否有效 | 次批 |
| RCEW-only | 无 | 无 | 有 | M3单独是否有效 | 次批 |

### 删除模块的具体含义

- No-CRFB：关闭类别响应反馈更新；RGRP改用已存在的非类别响应读出接口，不另造一个同功能注意力来代替M1。该行测“移除M1及其向M2提供的类别引导”的整体影响；接口耦合再由下节替换实验分离。
- No-RGRP：移除区域回写及最终多层区域描述，保留有效范围全局池化。M3需要的参考槽位生成仍保留并计入M3，不连带删除M3输入。报告分类头维度和参数变化。
- No-RCEW：去掉参考证据残差及其参考计算，保留M1/M2和相同分类训练。
- Plain：同样的VV/VH输入、缺失极化处理和共享骨干，全局池化后分类；不能使用不同数据或多一套目标标签。

### 共同训练起点是本次真正需要补的环节

当前读出检查点是模块训练后的产物，不能先加载完整模型，再删模块、只调分类头，就称完整训练消融。

实施时使用同一模块训练前的R50初始化，统一骨干可训练范围、阶段顺序、源样本批次、参考来源与停止规则。若找不到未受候选模块训练影响的源初始化，则统一回到相同通用预训练权重；不是只给某个对照更差的初始化。

保留当前的分阶段优化方式，不默认全骨干解冻、不改成新联合架构。每个阶段中，各配置的共同参数用同样训练规则；模块不存在时仍训练该阶段本应更新的共同参数。

M3当前是固定锚定参考路径。完整重放必须能从原始输入重算该路径，而非只读取评价队列现成残差。锚定编码器可共享冻结缓存；它属于方法实际计算，参数、存储与建立缓存成本都要记录。若改成随新版特征实时重算M3，那是新优化变体，不能悄悄替换本次固定版本。

启动训练前只做两项必要检查：同一原图前向能重放当前得分；禁用某模块后，预测图中确实没有对应更新路径。这两项分别防止测到错误版本和名义消融未生效。

## 四、第二优先：公平方法对比

| 对照 | 为什么需要 | 复用/补充方式 |
|---|---|---|
| 共享R50 + 全局池化 | 判断是否只比弱旧读出好 | 与Plain消融共享一次运行 |
| 共享R50 + SE或CBAM | 判断类别反馈是否优于通用注意力 | 选一个先做，不同时铺开多种相似基线 |
| 同骨干 + 简单类别原型/参考聚合 | 判断参考案例本身能解释多少收益 | 固定32源参考、相同区域输入与更新范围 |
| 当前完整模型 | 本文方法 | 与Full消融共享一次运行 |
| 1至2个近年SAR分类方法 | 形成与领域方法的实际比较 | 优先核查SCRC-Net、PGMNet的完整实现和输入需求后确定 |

近年方法须依据原文及可核实实现复现。仅做简化实现则明确写“适配变体”，不冒充原论文完整模型。额外文本预训练、物理属性或目标无标签数据改变信息条件时，单独分组报告。

公平不等于所有方法强制同一学习率。给予同等源验证调参机会，采用紧凑的学习率/训练长度范围；按源验证确定后冻结，再跑评价集。最终评价378条不用于挑最佳倍率、轮次或基线参数。历史开发集参与过研究，不能称为全新盲测。

## 五、第三优先：内部机制替换，不靠删模块包办解释

| 核心主张 | 最有区分力的替换 | 需要固定的内容 |
|---|---|---|
| M1的类别响应提供有效选择 | 均值、内容注意力、类别响应反馈 | 插入位置、通道宽度、训练策略 |
| M1帮助M2找到区域内判别证据 | 同区域均值、内容引导、类别响应引导 | 区域定义、读出容量和上游版本 |
| M2保留区域身份有用 | 分区身份保留 vs 同输入范围合并读出 | 图像范围、极化、投影维度、训练预算 |
| M3的类别证据回写优于搬运特征 | 参考特征聚合 vs 类别证据聚合 | 同参考、相似度输入、融合位置和配套训练 |

已有当前M1→M2读出三组可复用，不立刻重复训练。历史M3的精细匹配没有优势，不把“精细软匹配优越”作为当前主张。需要在统一新载体下重做的关键内部替换是M3的消息构造，以及M2区域身份；不再扫描所有插入位置。

受控干预指导训练保留。已有同预算的继续训练与干预训练比较先沿用，不把教师筛选救回等同于学生模型收益。若正文把该训练策略列为独立有效贡献，则必须在统一最终配置下补“普通继续训练/同数量普通选样/干预选样与优势学习”比较；尚未证实的增益不先写入结论。

## 六、数据扩展顺序与最小工作量

已有资产核查后，可提前做一个低成本外部验证：**当前OSS2冻结组合→OSS1的921条、742艘船、21个过境查询**。沿用已有合法性清单，按当前实际源训练/选模暴露更新排除条件，再从原图生成当前输出。旧特征不能直接顶替新前端；该方向无需先训练OSS1源模型。它可与OSS2统一训练入口准备并行，不能称为OSS1数据集内复现。

1. OSS2：先完成统一核心五行消融和主要对照；随后补三行单模块。当前开发范围内先把证据链做完整。
2. OSS1：沿用四类覆盖充分的既有跨场景协议，跑Full、Plain和OSS2中确定的最强合理简单对照。先验证系统，不重复所有内部排列。
3. 自建24港：用已确定的类别和跨场景划分重复上述三组；类别数、缺类与参考覆盖按真实队列报告，不能用OSS2四类检查点直接当八分类模型。
4. F_0921：保留其独立数据集价值，先核对既有协议对应当前类别体系及输入；按同样三组推进，不借本轮重新定义数据集。
5. 跨数据集：在共同类别、共同可用输入上，先做一个固定方向的Full/Plain/最强简单对照。只有源数据拟合，目标不重新调参；若用了目标支持，另列少样本适配协议，不与零目标标签混报。

跨数据集不是替代数据集内跨场景。数据集内消融与跨数据集验证回答不同问题。现有历史实验能复用哪些、哪些需当前版重放，见 `REUSE_DATASETS_ZH.md`。
