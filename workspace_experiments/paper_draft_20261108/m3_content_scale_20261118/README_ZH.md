# M3内容驱动混合粒度：代码候选

2026-11-18。已实现并通过算子及真实chip到分类输出的前后向检查；**训练更新0步，门控未训练，正式模型和论文结果不变**。

## 1. 本轮新增能力

不是将固定40网格读出改名为动态粒度，而是新增一个局部内容门控：对每个父区域决定使用一个粗槽，还是保留它的细子槽。查询、参考、VV和VH分别产生决定；同一极化的查询与参考共用门控参数。输入没有查询标签、港口或船只身份。

8个父组由原20细槽组成：框内2组各4子槽，侧向4组各2子槽，轴端2组各2子槽。粗组不跨框内/侧向/轴端，也不把两端、两侧合为同一粗组。**本轮最细仍是原20槽，并未进一步细分为80槽**。全粗至多8个有效槽，全细至多20个；为方便可微计算，张量保留28个候选。

输入chip不缩放。layer1在原生40×40网格读出；M1处理后的layer2在原生20×20网格读出，不先插值到40。两个读出的细槽描述拼接为768维；粗描述用细槽的layer1读出质量加权平均得到，再进入非线性匹配编码器。对layer2部分，这是保留细槽描述后按共同质量合并，不声称等于在layer2直接池化一个粗掩膜。

## 2. 选择如何起作用

令父组g的子槽为C(g)，其质量为m_i、总质量M_g=sum_i m_i。以每个细槽通道归一化后的组内加权均值及离散程度作为门控输入。VV/VH各自使用1536→32→1的MLP，输出p_g，p=1表示选择细槽。

- 训练auto模式：g=p，使用可微软选择。
- 推理auto模式：g=1[p>=0.5]，父粗槽和子细槽互斥。
- 对照模式：coarse、fine、soft、hard；另有显式override用于固定/打乱门控对照。

粗质量为(1-g)M_g，子质量为g m_i。粗回写覆盖为(1-g)乘子覆盖之和，子覆盖为g乘原覆盖。因此每个父组的总质量和逐像素覆盖守恒。这里的质量是read40覆盖密度之和，不是原像素面积。空极化无正质量；同时检查read40和read20，只有两层都无法区分子槽时才回退粗槽。两套网格不嵌套，不能只检查浅层。

门控进入的是归一化前的候选质量和回写覆盖，不是把描述乘一个随后会被LayerNorm消掉的常数。选择后不把细槽再平均回父槽。

## 3. 接入完整M3

原生chip → layer1与M1后的layer2 → 原生网格20细槽 → 8父槽/20细槽候选 → 内容门控 → 28候选的有效质量 → 区域内逐对匹配 → 每个查询槽的类别证据 → 对应覆盖回写 → layer4 → 原分类读出。

沿用已实现的完整逐对T与整体正反轴向假设；T直接影响每个查询槽获得的参考值，不压成行列边际外积。双轴向假设不是可靠船首检测。三个区域共用每个查询/参考/极化的整体轴向分布，候选位置与回写覆盖对应。其他类别上下文保持uniform版本，不额外加入关系上下文改动。

M2/PCEA仍使用原20槽语义；只替换M3专用desc/mass/write。原layer3末端回写位置不变。全骨干、已有模块、门控都可联合更新，BN运行统计保持固定。参考每次更新后重编码，不使用陈旧特征缓存。

与上一轮固定读出相比，这版同时接上已实现的逐对匹配能力，因此后续尺度选择消融必须使用**相同逐对匹配器与同一特征来源**的coarse/fine/固定配额对照，不能把整个组合相对旧模型的差值全归功于门控。

## 4. 文件与调用

- `model.py`：当前完整模型候选、Inputs、prepare、训练目标和优化器分组。
- `content_selection.py`：候选组织、内容门控、守恒的质量/覆盖选择。
- `native_masks.py`：原生像素掩膜到40/20/10网格的读出与覆盖。
- `verify.py`：机制与真实模型前后向检查；不执行optimizer.step。
- `verification.json`：检查数值；`integration_local.json`仅本地保存案例与分数。

```python
net = Model(selection_mode='auto')
net.train()  # selector soft; backbone BN running statistics stay fixed
optimizer = torch.optim.AdamW(net.optimizer_groups(), weight_decay=.01)
loss, logits, terms = net.objective(query_data, query_rows, reference_data,
                                   reference_rows, weights=sample_weights,
                                   budget_weight=0.)
loss.backward()
# A training runner, not verification, owns optimizer.step().
net.eval()  # selector hard; rebuild reference features for this mode
```

`objective`使用原分类CE+.02辅助CE，提供显式可选的额外细槽预算惩罚；默认系数0，尚未选择预算超参数。没有实现MSViT的Gumbel/STE或GBaS，不称为MSViT复现。没有自适应打包或FLOPs节省结论。soft训练/hard推理差异、门控是否退化为固定模板，需要配套训练后评价。

现有工程依赖沿用本地相邻研究模块及检查点；这是接入当前工程的实验候选，不是脱离依赖的独立发布包。

## 5. 已验证与未验证

全细配置能重放同参数20槽逐对匹配；总质量与逐像素覆盖守恒；硬选择不同时保留父子。保持父均值、改变子内容时，粗配置不变而细配置回写改变，说明细子信息没有被重新平均掉。相同行列边际下，完整T与外积回写不同。无合法参考/缺极化保持空证据。

真实2条既有开发chip和16条合法源参考：分类损失可以训练两极化门控；切换门控影响最终logits；M3关闭时各选择模式输出完全一致。检查未使用目标标签选择门控，也未启动全量评价或调参。

这些证明代码接入与梯度路径，不证明分类增益。门控参数仍随机初始化；两个案例的粗细偏好和分差不能解释成学会了有效物理机制。下一步才是相同数据、起点和预算的配套训练与对照。

最终检查数值：20槽全细重放误差1.36e-9；独立正反轴重排误差低于1e-15；真实最终分类损失对VV/VH门控梯度范数0.01883/0.04925（预算项权重0）；翻转查询粗细选择导致logit最大变化0.08477；M3关闭时选择模式输出差0。8种原生旋转/翻转的M2覆盖重算误差0；read20可区分而read40不可区分的回归案例已通过。门控参数98,434；真实2查询/16参考前后向峰值显存约3.82GiB，不是生产延迟或大batch成本测量。
