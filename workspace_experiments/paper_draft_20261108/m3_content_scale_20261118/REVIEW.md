## 已确认问题

### [P2] 可细分性漏看 read20，强制丢掉可用的深层细节

位置：`native_masks.py:31-38`；影响路径为 `model.py:95-100`、`content_selection.py:65`。

当前 `eligible` 只比较子槽的归一化 `read40`，据此认为子槽不能提供不同信息；但实际 fine 描述子是 layer1/read40 与 layer2/read20 拼接。origin-zero 的 40 网格单元边界为 2,6,10,...，20 网格为 4,12,20,...，两者不嵌套。因此子槽可以落在同一个 40 网格单元内，却跨过 20 网格边界。此时深层读出不同，`eligible=False` 仍使所有模式（包括 `fine` 和 override）强制使用粗父槽，门控无法恢复这部分证据。

## 1. 粗细互斥门控

- 先明确 `g` 的语义。若 `g=1` 表示粗，同一父区域的粗质量为 `g*M`，每个细子区域质量为 `(1-g)*m_i`，其中 `M=sum_i m_i`。粗候选只能合并同一极化、同一语义区域的子槽；不能跨框内/侧向/轴端合并。
- 硬前向下父粗候选与其细子候选互斥。若采用连续互补权重，则是软粗细混合，不能称硬互斥；可以作为明确的设计选择，但不能将两套完整质量同时保留。
- 门控必须影响实际进入匹配及回写的证据。仅将描述子或池化 mask 乘一个常数再归一化，会被池化分母、LayerNorm、余弦归一化或区域质量归一化抵消。门控质量应在候选拼接后、区域归一化前进入匹配。
- 粗描述子应从线性读出/原生覆盖构造后再进入非线性 `encode`。粗平均已编码的 key/value 与粗原生读出后编码不是同一操作，不能在对照中混用解释。
- 原生读出使用 layer1 40x40；layer2 插值到 40x40 不代表新增独立细节。输入不缩放、候选并集和实际回写位置须可追溯。

## 2. 质量与空间覆盖守恒

- 对每个样本、极化、父区域，门控前后选定质量定义下的总量不变，零质量子槽不能因门控变为正质量。保留原像素质量、read 覆盖密度之和与池化分母的不同含义。
- `NativeReads.one()` 的 `read40` 是 `cell_mass(native,4)/cell_area(40)`，而 `pool_multiscale` 的描述子归一化分母是 `read40.sum()`。粗描述子若要等价于合并 read mask 后直接池化，应按这个分母合并细描述子；不能不加说明地用原生像素质量替代，在边界 Voronoi 单元面积不等时两者不等价。
- 当前回写直接执行 `einsum('bshw,bsc->bchw', write, message)`，没有后续 token 维归一化。粗覆盖应是其子覆盖之和，细/粗覆盖分别施加互补权重；若两套覆盖都完整保留，将重复写入。同一常量 message 的门控前后逐像素回写应相等。
- 不能只验证质量总和：质量守恒而覆盖落到错误位置，仍然改变机制。查询与参考独立选择粒度，位置/区域/覆盖必须随候选对应；VV/VH 也不要求选择相同 token 下标。
- Sinkhorn 带 dustbin，返回的是真实 token 间子矩阵，质量可以小于 1。不要把 `T.sum()==1` 当守恒标准；应检查输入候选质量和回写覆盖守恒、非法条目为零，以及匹配后使用的实际行质量一致。

## 3. 完整 T 到空间回写

- `AxisCoupledMatch` 的有效路径是 `T -> sum_j(T_ij*v_j)/row_i -> 按类别聚合同类参考 -> 每个查询槽的类别证据 -> 对应 write_i`。不可在原型形成前平均查询槽，也不可默认改回 `row(T) outer col(T)`。
- 旧实现的 `arm='aggregate'` 与 `coupling='paired'` 可以同时出现：在轴向版本中，是否压成外积由 `self.coupling` 控制，不能仅凭 `arm` 名称判断机制。
- 当前 `REGIONS` 固定为 `0:8/8:16/16:20`，`positions` 固定 20 项，`field=torch.cat(fields,1)` 默认相同顺序。增加粗候选后需要共同更新区域索引、几何中心和 field/write 顺序；漏掉粗候选会使门控看似存在但不参与匹配。
- `slots/local_slots` 还供 M2 和 PCEA 的 `region_integrals` 使用，不能因扩展 M3 候选而直接替换其 20 槽语义。可在 matcher 内构造混合候选，或只扩展 M3 专用的 desc/mass/write；无须重构其他模块。
- 双轴向权重应仍是每个 query/reference/polarization 一组，在三语义区域共享；若逐区域或逐 query-token 各选一个全局方向，就改变了原本的整体方向假设。粗候选中心必须按候选定义处理，首尾反转下候选组须闭合。
- `reference()` 只返回 `desc/mass/available`，`LiveFull.finish()` 只拼接这三项。如果新 matcher 依赖逐样本位置或额外 gate 元信息，必须显式传递；若使用固定候选位置且已把 gate 编入 mass/write，则不必新增无用字段。

## 4. 不可用极化与空证据

- 既有 matcher 的实际可用性来自 `legal[:,:,p]`、query/reference 区域质量及 token 正质量，不是描述子是否为零。LayerNorm 仿射参数可使零描述子产生非零 key/value，故不可省略质量与合法性屏蔽。
- 查询缺某极化时，该极化的候选质量、写入量和有效计数须为零；参考缺某极化时不得贡献该极化的类别均值、竞争上下文、方向得分或原型。不能从另一极化补正质量。
- 只有一个可用参考类别时，other-class context 为零；所有参考非法/某区域为空时，不能通过 softmax 得到伪均匀证据。已有 relation context 使用显式掩码和安全空分母，新路径需保留该行为。
- 保留空参考分支、缺失类别的 valid mask、有限前向及有限反向。不能将 `-1e4` 无效 local logit 直接当作可用分类证据。
