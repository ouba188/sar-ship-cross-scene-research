## 实际发现并修正的问题

最初把“有VH图片但没有有效目标框”当作“VH完全缺失”，使样本18767的基础路径偏离历史模型。旧基础路径仍会读取这幅图的背景；M1/M2/M3却应屏蔽它的目标证据。现已将图片缺失、关联失效、目标框缺失分开处理，真实chip重放通过。

五点采样的角度减法从Python浮点计算恢复为原实现的float32张量运算；同输入同骨干的6条双极化比较中，five描述与旧实现差为0。剩余原图到历史缓存的微小数值差来自特征重算数值路径，在目前覆盖上没有预测翻转。

默认独立测试本轮运行13项：10项通过，3项需要显式旧目录的迁移测试跳过；后3项已由迁移支线在旧目录材料可用时实际验证，并非未实现的占位测试。

## 重跑

```powershell
python -m unittest discover -s tests -v
python tools/validate_raw.py
python tools/check_portability.py
```

默认单元测试不依赖旧实验目录；需要原始模块迁移对照时，设置 `M123_LEGACY_ROOT` 为原 `model_closeout_20261023` 后再运行单元测试。M3完整迁移：

```powershell
python tests/test_m3.py --legacy-root $env:M123_LEGACY_ROOT --assets-root assets --device cuda
```

`--extract` 另外检查原图局部描述。上述迁移工具允许读取旧结果；正式 `sar_m123` 推理包不允许依赖它们。`check_portability.py` 会复制最小实际输入与模型资源到系统临时目录，并禁止子进程读取原工作区，运行后清理临时副本。
