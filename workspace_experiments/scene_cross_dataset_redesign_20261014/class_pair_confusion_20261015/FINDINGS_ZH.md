# 源端易混淆类对选择：严格完整模型的配对验证

日期：2026-10-15。结论：**这一版“只保留最易混淆类对”的改动未产生可推广的净收益，不升为论文模块。** 这不否定类别参照/关系修正本身的条件性收益；它回答的是“源端常分错的类对是否应得到更多关系权重”。

## 为什么试、怎样试

此前固定28类对关系在六港**异采集**支持下平均 BA +0.45点（相对无关系普通双路），但学习28个权重在严格 `B=16` 中没有独立净收益。这提供了值得利用的收益空间，也提示直接学习全部权重可能不是合适接入。实验预先固定：在合法源训练样本拟合专家分类头，用独立的源留出采集验证集求每个类对的双向软混淆分数

`s(a,b) = mean[p(b|y=a)] + mean[p(a|y=b)]`。

按分数取前14对（`confusing14`），与后14对（`easy14`）、固定随机14对（`random14`）、全部28对固定关系（`all28`）以及无关系普通双路（`plain`）对照。选14是预定的“总共28对的一半”，没有扫数量。所有14对版本以**源训练集关系能量**补偿到与全部28对一致；实际每折倍率均约2。原专家核/关系核比例 `.75/.25`、ridge8、两头 `.5/.5` 融合、骨干、源先验和目标支持全部不变，类别选择不看目标标签。

覆盖 OSS1/OSS2 各4个留采集折，以及24港语料6个留港、8个查询场景；每折同一查询、同/异采集B16各5组支持。共16折、160个配对支持单元、800行模型指标。没有新骨干训练。`experiment.py` 每个单元的 `plain` 与 `all28` OA/BA和船级结果均与已归档完整模型**逐项一致**；若不一致会中止运行。`source_selection.json` 逐折记录源验证计数、混淆分数及实际选中类对。

## 完整模型结果

下表为 `confusing14` 相对 `all28` 的 OA/BA 百分点。先平均每折5组支持；公开集再四折等权，24港先在同港折间平均、再六港等权。正值才说明“挑难类对”胜过全部类对。

| 数据 | 同采集 OA/BA | 异采集 OA/BA | 异采集BA正折数 |
| --- | ---: | ---: | ---: |
| OSS1 | -0.58 / +0.06 | -0.20 / -0.53 | 1/4 |
| OSS2 | +0.10 / +0.22 | -0.01 / -0.21 | 1/4 |
| 六港等权 | -0.05 / -0.03 | -0.43 / -0.27 | 3/8；1折持平 |

异采集条件下，`confusing14` 相对 `easy14` 的 BA 为 OSS1 `-1.09`、OSS2 `+0.22`、六港 `-0.16`；相对固定 `random14` 为约 `-0.01/+0.41/+0.06`。因此不能把全部类对的旧收益转记到“源端混淆选择”名下，也不能说“只要降到14维就涨点”。六港中 Qingdao 异采集相对 `all28` 仍有 `+0.42` BA点，Singapore `+0.25`，Port Klang `+0.07`；Ningbo、Shanghai 退化，Jebel Ali 持平。局部正例保留，但目前找不到预先可识别的、足以支撑部署的共同边界。

## 数据层面的原因定位

简单解释“源端选错了目标易混淆类对”**不符合主要证据**：以前述普通双路预测定义目标错误类对，源端前14对在 OSS1/OSS2/六港的异采集查询中分别覆盖平均 `81.1%/79.9%/73.7%` 的重复错误事件；源混淆分数与目标错误对频数的逐折秩相关均值约 `.47/.60/.26`。这是诊断中使用目标真值，**没有反过来改变选择或模型**。目标错误事件在5次支持抽样中可重复出现，不当成独立船只。

更有解释力的是：**出现错误多，不代表这条类对参照能提供足够清楚的纠错方向。** 在独立源验证采集上，选中类对对应的类别参照坐标区分两类的平均AUC，OSS1/OSS2/六港分别为 `.800/.720/.737`；后14对为 `.962/.915/.878`。前14对的AUC在16/16折都低于后14对。选中子图的平均谱连通间隙也更小（`.994/.738/.798`，后14对为 `1.475/1.688/1.318`），但**并非每折**如此；这提示关系几何也可能被偏向少数难类对，而非已证明的单独因果根因。关系能量已匹配，故不能把退化简单归结为核强度变小。

在目标预测中，以 `all28` 为参照，改成 `confusing14` 的重复查询事件救回/新增错误：OSS1异采集 `2/4`、OSS2 `11/13`、六港 `6/12`；这解释了为什么“覆盖了大多数错误对”仍不能换来平均OA收益。六港逐港/逐类、源验证少数类计数见CSV。OSS1源验证最少类每折仅1–2张，混淆估计易波动；但OSS2最少类11–13张、六港19–120张，且异采集平均依然不升，因此**不宜把整个失败都归为OSS1样本过少**。

可支持的根因判断是：**把源端错误频率直接当作关系特征的可用纠错证据，学习目标错位。** 部分效用损失也可能来自删去其他类对后改变了核几何；本轮没有将两种作用单独因果分离。若以后研究类别关系，先从已有案例中检验“正确类的支持残差/竞争类margin能否被某组关系方向改善”，再设计选择器；这不是允许现在根据目标测试标签重挑类对。本轮不追加 `k` 网格或目标选优。

## 文件与验证

- `experiment.py`：冻结特征逐折重算、严格源端选择、全量旧臂精确回放；`analyze.py`：折/港等权配对汇总与逐类救回/损害；`diagnose.py`：源端易混淆对覆盖目标错误的比例；`pair_separation.py`：源端参照坐标可分性和关系图结构。
- `MAIN_EFFECTS.csv`、`PORT_EFFECTS.csv`、`FOLD_EFFECTS.csv`、`PAIRED_DRAW_EFFECTS.csv`：各聚合层的OA/BA差值；`ALL_CASES.csv` 与 `RESCUE_HARM_BY_CLASS.csv`：查询层诊断；`SOURCE_SELECTION.csv`、`SOURCE_PAIR_DISCRIMINABILITY.csv`、`TARGET_CONFUSION_ALIGNMENT.csv`：源选择与数据边界。每折的 `metrics.csv`、`cases.csv`、`source_selection.json` 保留原始计算输出。
- 这不是独立确认集；每折仅一个既有SAR-R18训练种子，五次支持抽样不是五次训练。三港目标查询仅出现3类；BA按实际出现类别算，比较应看同折配对差值。没有新方法收益，也没有修改论文或旧主表。
