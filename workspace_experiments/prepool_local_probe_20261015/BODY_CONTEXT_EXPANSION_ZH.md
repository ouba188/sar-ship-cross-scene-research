# 船体与环带扩围方案

日期：2026-10-15。状态：第一阶段扩围完成。下文保留事前方案，执行结果见 `body_context_expansion/FINDINGS_ZH.md`。

用户明确要求：动态加权也纳入扩围，不因本轮弱信号提前排除。

## 已有证据与要回答的问题

首轮五个源模型池、六个目标采集、642个查询，结果见 `body_context/FINDINGS_ZH.md`。环带补充的跨采集完整模型OA/BA净增0.229/0.368个百分点；船体与环带等权组合跨采集BA下降0.316个百分点，同采集BA提高0.521个百分点。动态加权尚无额外目标分类收益。

不能将上一轮结果等同于动态机制已经充分接受检验：15次条件训练中14次按源端BA选择了零初始化，退化为加性组合。训练末态并非没有参数变化，但概率扰动很小。

扩围要同时回答：更多采集与船只上环带证据是否仍有用；实际学到的动态权重是否在某些条件下优于静态权重和加性组合。原始表示、门控结构、作用幅度及完整读出保持不变，不把增加覆盖与修改架构混在一轮。

## 固定比较清单

| 方案 | 用途 |
| --- | --- |
| 原完整模型 | 共同协议下的净收益起点 |
| 环带补充 | 首轮跨采集正信号的主候选 |
| 船体+环带直接融合 | 同采集正信号与加性信息对照 |
| 源端选择的静态/动态加权 | 保留首轮完整学习和选择流程，允许选择零步 |
| 固定600步的静态/动态加权 | 在新增任务结果出现之前冻结训练长度，检验实际学习后的权重 |

固定600步是本次扩围前新增的预设比较，不声称首轮已经预设了这种部署方法。两个版本分别报告，不能按目标场景的结果选较优者拼成一个方法。

动态版与静态版使用相同源数据、损失、训练步数、支持任务和三个种子。复用已有缓存与末态；缺失的种子0末态按原种子/任务次序补存，保留既有源端选择结果。复用原模型池时不为扩围重新训练骨干。新增港口需要新的合法源域模型时，沿用源端排除规则，而不借用见过目标的自监督模型。

环带输入只用于逐样本调整船体坐标，并保留独立船体/环带分支。只在需要解释实际非零门控时使用原定的门控输入置乱；不将零门控的置乱不变当作新的机制证据。

## 扩展顺序

1. 优先在现有留出港增加未参与首轮评价的采集批次，再覆盖其他港口。新增查询/支持仍满足既定源目标采集与船只隔离，按数量和类别覆盖确定资格，不按方法涨点筛场景。冻结新任务清单后评价。
2. 保留B16，并在确有足够支持及独立查询的任务上增加B32/B64。预算比较使用共同可行的查询集合、配对抽样；完整B16覆盖另列，避免因大预算筛掉困难场景而误认预算收益。
3. 随后优先OpenSARShip 2.0，再评估F_0921；数据集间分别报告。此阶段尚未启动，也不将现有预训练模型或局部缓存视为必然满足新数据集的源端限制。

新采集尚未参与本轮，不等于从未参与历史研发。首轮开发结果、新增覆盖、确实独立的证据分别标注，不混称独立测试。

## 怎样认可收益

保留同采集与跨采集两种评价，按类别、场景、支持数量解释收益；同时记录OA/BA、概率风险、支持关系变化及实际计算成本。不要求动态版胜过所有方案或所有场景。

如果动态处理在某种明确数据条件下产生可重复且值得成本的净收益，可以作为有边界的有效组件保留。若固定600步仅改善中间关系而未改善完整系统，则分别陈述；若源端选择版本没有保住有用末态，再分析选择口径，不用新目标标签反向调整选择规则。
