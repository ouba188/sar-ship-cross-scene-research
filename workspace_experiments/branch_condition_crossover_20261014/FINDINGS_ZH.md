# 两路是否具有同采集/跨采集条件分工

日期：2026-10-14。独立轻量诊断；未重训图像编码器，未修改当前类别对比模型。

## 结论

**目前不能把两路写成“R50负责同场景、R18负责跨场景”。** 在冻结特征上新增R18单路的源分类头后，R18单路与R50单路的优劣取决于目标数据、标注预算和读出方式。OSS2在共同基础头参与融合时，R18相对R50的BA优势跨采集大于同采集；但把两个专家单独比较，OSS2 B64反而是同采集优势更大。F_0921 B64两种条件下均是R50单路更强。

## 配对协议

复用 `external_scene_transfer_20261013` 的20个采集任务、每任务5次支持抽样、同一批查询和逐类配平的B16/B64支持集。每个数据集各5个实际采集组；F_0921五采集子集166条查询、164艘船、6个查询类别，OSS2为314条、310艘船、8个类别。OSS2支持还匹配GRDH/SLC产品类型。这里比较的是**同次/其他采集的支持**，不等于严格同一完整SAR大景或同一产品。

使用已有共同源几何及28854条源样本，R50与双路原源头/预测不变；仅拟合一个R18单路平衡岭分类头，参数与原R50源头一致：`RidgeClassifier(alpha=1, class_weight='balanced')`。R18保留源几何的64维坐标作源头、原冻结R18核作支持残差关系，支持ridge=8。比较R50、R18、双路专家概率，以及它们各自与**同一个**R50 C4基础概率的0.5融合。每组适配按原支持标签分别重求系数，不用查询标签拟合或选择模型。

R50基础、R50完整融合、双路完整融合与原存档概率全部逐元素回放一致，最大误差0；本轮新增的R18单路是预先固定读出配方的诊断臂，不能称为所有可能R18单骨干方案的最优值。指标先对每采集的5次支持抽样平均，再对5个采集组等权平均；BA按该采集查询实际存在类别计算。

## 结果：专家单独比较

BA百分比；括号是R18减R50的百分点。专家单独使用，没有C4基础头。

| 目标 | 预算 | 同采集：R50 / R18 | 跨采集：R50 / R18 |
| --- | ---: | ---: | ---: |
| F_0921 | 16 | 27.048 / 23.396 (-3.652) | 24.019 / 22.582 (-1.437) |
| F_0921 | 64 | 40.544 / 32.369 (-8.176) | 27.995 / 21.526 (-6.469) |
| OSS2 | 16 | 23.563 / 23.566 (+0.003) | 19.700 / 20.995 (+1.295) |
| OSS2 | 64 | 28.899 / 35.241 (+6.343) | 25.873 / 25.944 (+0.072) |

OSS2 B64的单专家对比**不支持**“第二路跨采集才比第一路强”：其同采集优势更大。逐采集平均中，没有一个OSS2 B64采集组同时满足“R50单专家同采集更好、R18单专家跨采集更好”。

## 结果：接入共同基础头后

两臂均与相同的R50 C4基础预测0.5融合。括号仍为R18减R50，单位百分点。

| 目标 | 预算 | 同采集：基础+R50 / 基础+R18 | 跨采集：基础+R50 / 基础+R18 |
| --- | ---: | ---: | ---: |
| F_0921 | 16 | 25.474 / 26.562 (+1.088) | 23.631 / 23.422 (-0.208) |
| F_0921 | 64 | 42.718 / 36.436 (-6.282) | 28.138 / 26.500 (-1.638) |
| OSS2 | 16 | 23.172 / 26.290 (+3.118) | 21.836 / 25.572 (+3.737) |
| OSS2 | 64 | 35.714 / 38.500 (+2.786) | 26.527 / 30.865 (+4.339) |

OSS2 B64在完整融合中跨采集的**相对**R18优势比同采集大1.553点，但不是条件反转：两种条件下R18臂都更好。仅2/5个OSS2采集组在融合读出下呈现“同采集R50胜、跨采集R18胜”的严格反转。F_0921 B64则两种条件下均偏向R50。不能把2/5个采集组或跨预算波动包装成固定路由规则。

**OA不呈现同一强弱排序**：OSS2 B64的基础+R18相对基础+R50，OA在同采集为+5.866点、跨采集为+3.400点。上述“跨采集相对优势更大”仅指BA，可能涉及类别均衡与样本组成，不能替换成笼统的“跨采集识别更好”。

原双路臂 `Base+Dual` 减 `Base+R50` 的BA在OSS2 B64同/跨采集分别为+0.387/+4.230点，但这是**联合专家与共同基础头的效果**，不等于R18单独专家的条件优势。F_0921对应为-0.126/-0.550。单专家、共同基础融合、双路联合的相对排序会变，说明后续读出不可从分支分析中省略。

## 如何使用这轮证据

可以写：两路具有**条件相关、通过源判断和支持关系两条通道体现的互补性**；在OSS2的这套协议下，加入第二路对跨采集完整预测的帮助较大。不能写：第一路天然专管同场景，第二路天然专管跨场景；也没有证明一个只看采集关系就能部署的分支选择器。

数据层面的边界：采集组只有各5个且支持抽样共享查询；F子集没有全部八类；F语料有历史R18无标签预训练暴露；模型输入、预训练和训练阶段差异未独立拆开。本轮复用的是较早的紧凑读出，不含最新28个类别对比关系权重。要将条件分工写进**当前模型**，应固定其已训练关系模块，按同查询/同支持预算重做R50、R18、双路三臂及融合层比较，并报告逐采集、类别和支持覆盖的救回与误伤。不要用本轮目标结果去训练路由或挑分数据集赢家。

复现：运行 `run.py`；逐支持条件指标见 `metrics.csv`，等采集汇总见 `summary.csv`，逐采集分支差值见 `scene_effects.csv`，存档回放和样本规模见 `CHECKS.json`。
