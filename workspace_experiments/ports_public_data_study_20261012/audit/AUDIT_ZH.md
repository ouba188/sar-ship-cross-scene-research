# 24 港口与公开目标数据审计

完成日期：2026-10-12。仅使用已有清单、支持集、源域行索引和条件缓存；未拟合模型、未运行推断、未分析分类风险收益、未解码图像。审计脚本实际运行完成，退出码 0；所有输出位于本目录。

## 结论

1. 自建语料是 **38,091 行、24 港口**，历史 B=64 比较只有 **23 个可评估目标港、38,027 行**。缺少的 Melbourne 恰好只有 64 行，抽完支持集没有查询行；不是实验失败，也不是从训练语料统一删除。
2. 数据差异不仅是样本量。自建目标港各自只有 3–8 类，而三个公开评估队列均为 8 类；类别比例、支持集覆盖、重复船舶、产品类型、采集年份和显示域对比度均不同。不能直接把原始等港宏平均与公开数据集宏平均的差异全部归因于模型使用线索的方式。
3. e206 的可追溯预训练语料是 **F_0921_pool_v1 全 PNG 池**，不是由现有证据证明的“当前 24 港口全样本”。脚本未按港口/MMSI/产品留出，训练日志记录 345,590 张、40 epoch。当前池与三个目标均有身份重叠，不能写成“24 港口有曝光、OSS 没曝光”。历史精确像素曝光无法确认。
4. 主代理另做的五折同模型比较控制了本轮源域拟合和冻结模型参数；**没有重新隔离 e206 预训练语料**。这是必须披露的上游混杂，但本审计不认定它是差异的唯一或已证实原因。

## 成像与可用条件

从产品 ID 解析：自建全部为 GRDH，日期 2025-01-01 至 2026-02-24；OSS1 全为 GRDH，2015-08-23 至 2016-10-18；OSS2 为 2,746 GRDH + 999 SLC，2015-04-03 至 2016-07-12。年份、产品类型与数据处理流程同时不同，不能从队列比较单独识别某一个物理因素。

下表使用同一既有 `c4_condition_descriptors` 配方的显示域代理中位数；源数据均来自实际缓存，不重新提取图像。

| 字段 | 自建24港 | OSS2 | OSS2_GRDH |
|---|---:|---:|---:|
| VV原始芯片宽度（像素） | 64 | 69 | 61 |
| VH原始芯片宽度（像素） | 64 | 69 | 61 |
| bright-footprint fraction | 0.029358 | 0.021118 | 0.021545 |
| elongation proxy | 1.175007 | 1.214822 | 1.247743 |
| contrast proxy | 0.166667 | 0.041176 | 0.047059 |
| center-excess proxy | 0.094900 | 0.033796 | 0.040222 |

- 对比度定义为 `a=(VV128+VH128)/510` 上的 q95−q05；中心超额为中央区域均值减外缘均值。elongation 和 footprint 来自全图亮散射分布，**不是船体分割，也不是真实船舶形状或地面分辨率**。海岸、港区背景和显示拉伸都可能影响它们。
- 自建四项代理覆盖全部 38,091 行；OSS2 的 elongation/footprint 有 1 行无亮度超额而缺失，其余两项覆盖全部 3,745 行。缺失未填补。
- **既有缓存无 OSS1；主代理补算见 `../image_diagnostics`。** 本 `metadata.csv` 中 OSS1 代理及原始芯片尺寸保持空值，不能作为零值参与关联。后续补算结果以主代理目录为准。
- 自建入射角仅接受 sidecar `status=ok`，可用 28,628 行（75.16%），其余 9,463 行保持缺失。现有公开目标清单没有对等入射角记录，不能做三队列同口径入射角归因。
- 自建 `target_long_side_vv` / `target_occupancy_vv` 有 25,656 行；OSS2 的 `length_m`、`visible_length_px` 有 3,745 行。这些字段定义和来源不同，不能拼成一个统一的“船长”变量。
- `numeric_summary.csv` 给出每队列、每港口和各类别的缺失率及分位数，只做描述统计。均值、类内差异和收益之间的关联仍需主实验单独检验；不预设“越偏移，残差越有用”。
