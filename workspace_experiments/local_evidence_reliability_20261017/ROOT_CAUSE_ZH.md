# 设计逻辑还是数据问题：针对性诊断

2026-10-17。用户询问本轮局部读出/动态门控收益有限的原因。此次只检查代码、既有数据与源端梯度，没有更新模型、挑选目标参数或启动新训练。

后续状态：用户随后授权的2x2实验已完成，见`../support_task_alignment_20261017/FINDINGS_ZH.md`。多支持未提高跨采集BA；去辅助项反而三个种子均下降。因此下文的任务/梯度现象不能当作已确认的主要失效根因。保留本诊断原始判断与假设，不用后续结果改写历史。

## 判断

目前最明确的是两类任务对齐缺口：**门控使用的信息不够任务化，源端支持任务组织也缺少变化**。另有辅助目标相对完整分类目标的梯度失衡信号。它们比“数据太差”“局部信息没有价值”有更直接的证据，但尚未通过修正后的对照确认各自对最终收益的因果贡献。

不能把程序实现、组件设计、训练组织、原始数据的信息量混成一个问题。已有回放与替换实验没有显示门控断开或支持求解错误；局部读出也保留了小幅收益。问题是没有建立所声称的“当前任务值得使用哪个局部区域”的动态机制。

## 1. 组件判断的东西，比研究目标窄

`local_evidence.py:28`的门控输入是单张图像的框内特征、局部特征、位置和SAR统计；不包括当前支持集的内容/类别构成，也没有原完整模型的类别分数或混淆状态。

因此同一张查询更换支持组合时，**原始区域权重完全不变**。后面的支持中心化、SS/QS核、支持系数和最终预测仍会改变，不能误说整个模型没有利用支持集。

它可以学习“什么样的图像区域一般更值得用”，不能直接表达“面对这组支持、要区分这几个类时，这个区域有没有新增区分力”。后者才是此前希望发展的查询-支持关系条件化。

举例仅说明逻辑，不充当实测案例：同一查询的某块邻域纹理，在支持组合A中能区分同类与易混淆类，在组合B中所有类别都有；其任务价值不同，但当前门控对这张图给相同权重。共享表示可以间接适应部分情况，却不能让原始选区权重随支持变化。

这不是“图像质量门控必然无效”，而是它与当前研究目标存在明确的表达范围差距。需要纠正的是此前对设计能力的解释，不是先把弱结果归咎于物理因素不可获得。

## 2. 优化目标有完整分类监督，但两种推动强度不同

`train_reliability.py:44`实际损失为完整分类宏Brier加0.05倍局部检索CE。完整分类梯度确实存在；不能说模型完全没学系统收益。

新增只读诊断：加载12个已完成的dynamic模型，在原110个源拟合任务与27个源选择任务上分别计算两项损失对`gate`与`null_gate`参数的梯度，不执行优化器。三个训练种子共330/81个任务-模型评价，重用原有任务，不是新的独立数据。

| 终点梯度诊断 | 源拟合任务 | 源选择任务 |
| --- | ---: | ---: |
| 已乘0.05的辅助梯度/分类梯度范数，中位数 | 9.5946 | 15.2834 |
| 辅助梯度较大的比例 | 99.70% | 100.00% |
| 两项梯度方向余弦，中位数 | 0.7562 | 0.4528 |
| 两项梯度方向相反的比例 | 17.88% | 30.86% |

含义：名义上0.05的辅助项并不意味着对门控影响很小；在当前终点，它的梯度通常更大。该辅助项奖励局部特征本身的同类检索，而不是专门奖励“补上原系统尚缺的判别证据”。

边界：多数任务方向仍然一致，所以不能说辅助损失普遍与分类对抗。终点梯度不能恢复全程优化，也没有证明去掉辅助项必涨点。它提供了值得优先检验的失衡解释，不是唯一根因证明。

另一个应避免的伪修正：把分类损失换写成“新风险减冻结旧风险”，旧风险对新模块是常数，梯度不变。只改这个公式不会解决当前对齐问题。

## 3. 训练材料的组织没有充分呈现支持条件变化

`oss1_joint_geometry_20261017/train.py:22`为每个源采集固定一次查询划分；每个same/cross模式找到第一组合法支持后就在第55行`break`。每个查询采集最多形成一组同采集、一组跨采集支持任务。

`train_reliability.py:72`每步从这个固定列表抽任务，没有重新抽支持。四折拟合列表为27、27、26、30个任务，选择列表为7、7、8、5个。三个读出种子改变初始化/任务访问顺序，没有改变这份固定支持组织。

因此200步并不等于看过200种支持条件。测试有五次支持抽样，但训练并未对应提供同一查询的多次同模式支持抽样。这是可改变的任务组织限制，不等于必须新增成千上万张原图或目标标签。

现有源端固定读出诊断也表明，同一查询在不同上下文中的收益会变化；但那属于旧固定描述的诊断，不能直接当成当前动态模型已经能识别这些变化的证据。

### 源端留出曲线与有效监督

`source_learning_curves.csv`中dynamic的四折、三种子等权平均如下，均越低越好：

| 源端留出指标 | 第0步 | 第50步 | 第200步 |
| --- | ---: | ---: | ---: |
| 完整宏Brier | 0.805699963 | 0.805796717 | 0.805704752 |
| 局部检索CE | 1.490922 | 1.469306 | 1.509144 |

第0到200步仅4/12次Brier改善、5/12次检索CE改善；按折平均只有pilot两项均改善，另外三折两项均恶化。static和uniform总体也未改善，不能将全部问题归因于动态分支独有的输入限制。

这不与目标完整模型相对原模型的小幅正收益矛盾：比较基准不同。这里是同一读出从初始化到训练终点的源留出变化；主表比较的是加了读出的完整模型与旧完整模型。它进一步说明，尚不能把主表全部收益归于“训练学到了更可迁移的关系”。

稀有类局部辅助监督的实际覆盖如下。数目是去重查询，不是重复任务行；辅助可用要求查询有效且至少有一个有效同类支持。

| 类别 | 源训练：总数/有效/辅助可用 | 跨采集源留出：总数/有效/辅助可用 |
| --- | ---: | ---: |
| 渔船 | 12/3/1 | 5/4/0 |
| 原油轮 | 8/8/7 | 2/2/1 |
| 拖轮 | 7/0/0 | 5/0/0 |
| 海工补给船 | 9/1/0 | 2/0/0 |

当前有效掩码与旧源诊断一致，但旧表中“支持含同类，可计算AP”不等于该辅助损失可训练。例如唯一有同类支持的留出渔船查询本身局部无效，因此这一类有效辅助监督仍为零。

是否过拟合：检索CE先降后升与后期任务过拟合相容，但`training_loss`仅记录当步两个任务，没有完整源训练集的配对曲线，尚不能确证经典过拟合。可直接说的是源留出总体学习收益弱、有效监督不均，不能说是纯粹少训练了几步。

## 4. 原始数据层面能说什么，不能说什么

- 本轮是OSS1四个留采集折、199张查询、B16；少数类与独立采集覆盖有限。不能从四折结果判定所有中低分辨率SAR邻域都缺乏判别信息。
- 源选择材料中，拖轮5张、海工补给2张在旧固定描述诊断里均无有效局部描述。这些样本无法提供对应的局部选择信号，也不能把未生效解释成该类不存在有用邻域。
- 幅度、对比度或VV/VH比发生变化，并不自动等价于“更能分开当前船型”。上一轮环境/运动能解释部分图像变化，尚未建立“这些变化 -> 本次支持关系改善”的可预测链条。
- 新增统计从预测时置零会掉点，但从训练开始不用它，平均OA/BA反而更好。这排除了“模型依赖统计就证明统计带来净分类收益”的推论；不证明所有SAR观测条件都没有价值。
- 前一轮保存的真实图像案例只支持响应差异与计算路径，未标定真实尾迹、散焦、干扰强度；不凭外观推断物理根因。

## 5. 已确定的直接失效表现

相对区域门控的变化很弱：公共logit分量解释跨样本变异的中位数约96.11%；源端平均门控替换后全部top-1保持不变；匹配中心化特征能量后仍相同。

这定位了**动态选区没有额外起作用**，不是直接证明为什么没学到。输入未任务条件化、任务组合单一、辅助梯度较强，是具体可检验的原因，而不是三个已独立确认的因果结论。

## 6. 修正顺序，不增加无关复杂度

1. 保留当前静态局部读出，先在相同源数据、步数与支持预算下比较固定支持列表与同查询多支持组合；检查不同合法支持下的类别可分性与系统增量，避免把额外步数当作支持多样性收益。
2. 在匹配任务上做一次保留/去掉检索辅助项的对照，检验其是否提升局部关系却妨碍完整系统。不要仅凭梯度比就任意调几十个权重。
3. 若数据确实呈现可利用、可预测的支持条件差异，再把支持关系与原模型混淆信息纳入任务共享的选区；查询和支持使用一致的任务条件映射，保留SS/QS一致性。不是给每个查询边随意改分数后仍声称共享PSD核。

本次没有执行上述新训练。用户问的是原因，先把问题定位与下一轮必要的区分性对照讲清楚。无需要求每类每折都赢，但不能把尚未定位的失效仅归咎于数据不足。
