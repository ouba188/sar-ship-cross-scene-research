# 本轮验证与运行说明

## 实现验证

`python -m unittest test_sequence -v` 的4项针对性测试通过：

1. 固定4原像素采样间距；实际中心随90度旋转正确变换；船轴翻转180度只反转序列并交换侧线。
2. 用已知线性空间场核对实际采样坐标及双线性插值，没有把目标伸缩到固定长度。
3. 打乱为一一置换，内容与区域权重同步移动；反向操作与置换相容，反置换精确恢复原数据。
4. 两类读出器的轴向反读/侧带交换不改变输出；零初始化残差等于0，全部无效区域始终为0，内容层梯度确实非零。

提取实际15,252行、2极化、4旋转、2参考、3条线、49最大位置、64通道，float16缓存；143.15秒完成。没有目标框被本轮画布截断，超过最大条带长度会显式报错，本轮没有触发。

实际训练逐折/种子重放上一轮keep_refs预测，并验证0步残差精确返回冻结分数。最终分析另外比较旧分数文件，而不只比较top1，结果保存frozen_score_replay.csv。

最终完整分数重放最大绝对误差1.78814e-7，9组top1一致；最后修改仅为保存顺序与诊断表达式简化，5个Python脚本语法编译通过，未改变已训练算法或结果。

## 内存中断与恢复

首轮完成24次新分支拟合后，在fold2/seed2计算冻结基座分数之前发生Windows主机内存分配失败（46.3MiB）。原始日志保留为training.log；同时启动的覆盖诊断也因内存不足失败，未生成新结果。

修复仅涉及资源使用：缓存保留磁盘内存映射，按批传入GPU；冻结Ridge分数按512行分块计算。结构、权重、损失、训练批次顺序、数据划分和选步规则不改。新增显式--resume，复用已写入的完成组，只续跑最后fold2/seed2的3个新分支拟合。日志training_resume.log。RECEIPT.json的seconds仅对应续跑调用，不能误当27次拟合总耗时。

不终止或改动用户其他研究进程，不丢弃首轮结果。缓存精度与读取方式不是新增调参维度。

独立审阅确认36个测试组、27个新模型、108条选步记录、9条顺序干预均齐全，最后3组确实训练后按源验证选择step0。本次中断发生于新组训练前，不需要恢复优化器状态。审阅另发现将metrics作为完成标志时应最后写入，已将保存顺序调整为其他表格成功后再写metrics；本次未触发该缺口，不改变结果。
