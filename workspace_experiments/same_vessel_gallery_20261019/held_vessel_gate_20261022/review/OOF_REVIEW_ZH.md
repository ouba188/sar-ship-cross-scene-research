## 协议及旧实现证据

- A 不是单独的 ridge：`axial_strip_sequence_20261020/run.py:frozen_scores` 先读取 native-axis ridge，再叠加 `sampling_preservation_20261020/mse_aligned` 的 `keep_refs` 监督残差。OOF 必须重训 ridge、keep_refs、separated 邻域残差三层，同时重新拟合各层输入标准化，不能直接复用旧 A 或旧监督头。
- `native_axis_probe_20261020/probe.py:evaluate` 的 ridge 标准化仅取训练行，alpha 候选为 0.1/1/10，按源验证 BA、Brier 选择。`sampling_preservation_20261020/run.py:train` 的 keep_refs 标准化按训练行、60×64 对应位置统计；应复用其 MSE 版本，而非原 CE 版本。
- `neighborhood_level_split_20261021/run.py:standardize` 对每个极化的有效训练行分别统计 centered 描述子和 level，再拼接两个有效性标志；`Residual` 为 260→32→8。其 hidden 32 维不是跨重训模型统一的坐标。
- 协议改为 `[A(8), D(8)]` 输入是合理的：ridge 列需对应固定 class_id 0…7；两个残差的目标也应使用相同的八类 one-hot 编码。这样避免把不同模型的 hidden basis 混合训练门控。class-aligned 不代表分数尺度已经同分布。
- 旧外划分 `conditional_evidence_pilot/run_pilot.py:indices` 按 MMSI 和时间组织 train/val/test，并断言两两 MMSI、product 无交集。内层留船不隔离 acquisition 是协议明确限定的任务范围，不应额外要求本轮改成留场景。

## 对照与解释边界

1. 门控层应比较同一批外训练行、标签、权重、初始化、batch 序列、150 更新和 0/50/100/150 验证候选；输入都必须是同定义的 A、D 分数。常数和 score gate 的容量本来不同，正确比较是各 exposure 的 score gate 相对常数控制，以及两种 exposure 的 score gate 配对比较。
2. 两组最终评估应调用同一份 full-source A、D；OOF 分数只能替换门控训练输入。否则把更换基模型与更换门控训练暴露混在一起。
3. “同预算”只能指配对的门控拟合，以及每个内层基模型的同更新上限。OOF 额外训练三套基模型，整轮总计算量不相等；约 2/3 船只上的 150×128 抽样意味着每船重复暴露相对更多，不能称为等数据量实验。
4. OOF→full-source 的变化同时包含未见船误差、基模型训练量及分数/残差尺度变化。正负结果可以回答当前 OOF 门控方案是否有用，不能单独识别“去泄漏”的因果收益，也不能据负结果认定 OOF 原理无效。
5. 相同源验证集被 ridge alpha、keep_refs checkpoint、邻域 checkpoint 和门控 checkpoint 反复使用，且前轮研究也使用过它。这不等于 held MMSI 参与监督，但本轮是开发证据，验证结果不构成独立确认。既有 4,744 外测试观测也已经用于此前研究，不应称为全新锁定测试。
6. MMSI bootstrap 的区间条件于已拟合模型，不能把三次种子、三个相互重叠源集的外折或同船多观测当作更多独立训练重复。协议已经正确限定 bootstrap 的解释。

## 实际监督退化

`run.py:67–76` 允许按源验证选择零步，而旧 `Residual` 的输出层零初始化，因此选择零步时 D 恒为零。通过源选择日志、`exposure.csv` 和实际 OOF 数组交叉确认：**27 个内层邻域头中 12 个选择零步**。

下表是实际门控训练行中 D 非零的行数，分母是该外折全部训练行；数值直接从缓存读取，而非只依赖日志标签。

| 外折 / seed | 全源训练输入 D 非零 | OOF 训练输入 D 非零 |
| --- | ---: | ---: |
| 0 / 0 | 4392 / 4392 | 0 / 4392 |
| 0 / 1 | 4392 / 4392 | 2971 / 4392 |
| 0 / 2 | 0 / 4392 | 0 / 4392 |
| 1 / 0 | 4419 / 4419 | 2984 / 4419 |
| 1 / 1 | 4419 / 4419 | 4419 / 4419 |
| 1 / 2 | 4419 / 4419 | 4419 / 4419 |
| 2 / 0 | 4418 / 4418 | 2973 / 4418 |
| 2 / 1 | 4418 / 4418 | 1434 / 4418 |
| 2 / 2 | 0 / 4418 | 2879 / 4418 |

- fold 0 / seed 0：OOF 全部 D=0，`A+wD` 对门控参数的数据梯度为零；该门控没有从未见船误差中学到残差强度，最终却接入非零 full-source D。这组不能作为“已接受有效 OOF 门控监督但未能迁移”的独立证据。
- fold 0 / seed 2 和 fold 2 / seed 2：全源 D 恒零，最终评估对任何 w 都不敏感。后者即使存在 OOF 门控学习，也没有可改变最终分类的残差路径。不得把这些组的无变化直接归为门控不可学习。
- 其余部分 OOF 行 D=0，会降低有效梯度样本量；相同名义行数和更新次数不等于相同有效监督量。这和训练量减少及源验证选步一起构成本轮 exposure 改变的实际内容。

建议仅在本轮报告中明确这些组和限制，保留原始全部结果，不事后剔除组或改变零步选择规则。新增 `analyze.py:57–79` 已输出 active 行数等训练信号诊断；这些统计支持上述限定，但不能单独证明训练量减少导致了零步选择。

- OOF score − reference：+0.0141，区间 [-0.0426, +0.0704]。
- in-score − reference：+0.0422，区间 [-0.0425, +0.1257]。
- OOF score − in-score：-0.0281，区间 [-0.1053, +0.0431]；对应 BA 差值 -0.0186，区间 [-0.1040, +0.0681]。

因此，**本次固定协议和模型下，OOF score 没有显示相对 in-score 的稳定优势，两个 score gate 相对常数控制的额外收益也未得到清晰支持**。不应写成 OOF 必然劣于 in-sample、方法等效或 OOF 无效；这些区间也没有计入重新划分或重新训练带来的全部不确定性。两个 score arm 的净救回都集中在 seed 1，不能用平均小正值掩盖这一点。

`oof_score_source_mean` 的均值 OA 为 41.5121%，OOF score 相对它为 +0.0141 个百分点，区间 [-0.0140, +0.0424]。其常数取 `run.py:271` 的 full-source 训练行门控输出均值，并非用测试标签选择，定义合法；但现有结果尚未证明逐样本门控比这一全局强度替代更有必要。

## 训练信号与目标诊断

`analyze.py:57–79` 的导数是固定 A、D、w=1 处沿残差强度方向的加权 MSE 导数，不是分类准确率导数，也不是完整网络的参数梯度。实际 `training_signal.csv` 中 7 个存在有效 D 的 OOF 组全部倾向降低 w；7 个 full-source in-sample 有效组中 4 个倾向增大、3 个倾向降低。这支持“OOF 改变了门控面对的训练误差和局部目标方向”，但不能据此认定变化完全来自去除身份暴露，或认定优化器已充分利用该信号。

`diagnose.py:23–46` 使用测试真标签，为每个样本求 `[0,2]` 内使 MSE 最小的 w，并核对每行平方损失不增加；没有把这些 w 回写训练或选 checkpoint。已追溯其复用的前轮 scalar-family 可达性代码。`DIAGNOSTIC_SCOPE.json` 明确标为 posthoc、不可部署，这个边界正确。

实际汇总：逐样本真标签 MSE oracle OA 为 44.2313%，reference 为 41.5121%；各 seed 净救回 141/171/75。它仍误伤 11/12/5 个原本正确样本，并漏掉 scalar family 可救回的 20/19/4 个错误样本。可以据此说明平方损失与 top-1 的最优选择不完全一致，以及固定 D 的标量路径存在方向限制；**不能把实际门控接近零的收益全部归因于 MSE 不合适**，因为同一 MSE 目标的真标签逐样本最优解仍有明显空间。

该 oracle 的存在同样不证明这种空间能由 16→8→1 门控从合法源数据学到，也不证明换损失就会涨点。zero-D 监督退化、OOF/full-source 模型及尺度变化、有限优化预算、合法输入对所需权重的可预测性之间的相对贡献仍未被本轮因果区分。保留这些未解释部分比直接把负结果归咎于 OOF、优化器或损失更符合现有证据。
