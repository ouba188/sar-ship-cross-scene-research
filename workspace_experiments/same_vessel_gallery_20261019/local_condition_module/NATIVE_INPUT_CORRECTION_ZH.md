# 输入尺度纠正：原生像素裁边与补零

2026-10-20。按用户要求取消局部模块输入的逐图缩放。本次只完成预处理实现与实际几何覆盖检查，没有重新提取特征或训练，没有新增分类收益。

## 已修改

- 大图围绕检测目标范围中心平移裁边，小图居中补0；图像与T/O/R掩膜同步处理，不插值、不旋转。无可用目标框时采用图像中心，不能声称该情况有目标定位保证。
- 当前统一画布160x160。实际目标掩膜最大跨度133像素，另有一张108像素，强行裁96会截断目标；160是本开发队列的覆盖选择，不是测试准确率选优或物理尺度常数。
- 保留输入PNG的像素值及像素尺度；补边不归属任何区域，不参与区域池化。归一化/卷积感受野仍可能影响边界，不能说补边对网络完全无影响。
- 冻结stem后统一2x2池化，得到40x40响应，不再将不同原始尺寸通过逐图缩放变成统一船体尺度。该固定网络下采样仍会损失细节，与输入缩放是两回事。
- 保存裁剪偏移、有效尺寸、补边位置及各区域保留像素；如果未来目标超出画布则报出，不静默截船或缩小。

## 实际覆盖检查

复用本轮固定快照，排除确认错误31237后：30502张VV/VH视图，其中1张裁边，30501张补零；已有目标掩膜无截断。1421张没有有效目标掩膜，不能据此认定它们没有船。这里是全快照视图统计，不是测试船数或独立样本数。

单元检查覆盖：原始像素逐点保留、非方形输入、偏心目标、掩膜同步、补边为零、超尺寸目标明确失败，以及133像素目标在160画布中完整保留。

## 旧结果与后续使用

`prepare.py`默认生成新的`native_crop_pad/`缓存；`--legacy-resize`仅在独立`legacy_resize_replay/`重放旧96输入。原目录旧缓存、模型、结果没有覆盖，历史指标仍属于缩放版本。

当前训练脚本仍指向旧缓存，本次没有把新旧缓存混用。开展下一轮时需显式接入新缓存，重新训练局部补充通道；旧全局基线仍来自其历史预处理，不可声称整个系统已实现原生尺度。

新策略同时改变了细节采样和保留视野，后续性能差异不能全归因于尺度。旧面积占比的分组结论也不能直接沿用为新策略的门控。PNG原生像素不等于统一米制尺度，仍需原景像元间距及上游重采样记录。
