# 源端浮点裁片信息可用性检查

仅使用既定fold0源1821观测，1542训练/279验证，不读取测试图，不训练任何模型。逐对象用当前source_path明确产品和Patch_Uint8文件名，定位同产品Patch_Cal文件；没有经纬度近邻猜配。按产品Metadata的mds1/2极化顺序读取，再用逐像素秩对应检验，不能仅凭较亮波段猜VV。

检查维度、有限性、负值、浮点分位数及与原PNG的秩相关。预定两个转换诊断：255*sqrt(float/max)与255*float/max，不拟合逐图参数。它们仅检验显示归一化解释，不预设文件真实单位，不以目录名断定Sigma0。原产品metadata的calibration标志可能描述原产品，须与实际Patch_Cal文件标签分开报告。

只有核实对应和数值差别后，才设计分类补充实验；本轮统计不证明幅度有分类收益，不修改原输入、不替换已有模型。若需要出图，保持原像元，VV/VH分开，所有浮点图采用清楚说明的同极化共享显示范围，不以逐图拉伸伪造幅度对比。

首遍诊断发现多数图接近最大幅度归一化，但少数MAE较大，故补充预定义的幅度min-max公式作数据生成排查，保留前两公式，不据验证分类结果选显示公式。XML现实中有Metadata.xml与产品名.xml两种命名（目录还可能带(1)），按实际唯一非Ship XML读取，不改数据文件。

min-max未解释多数大误差。实际raw Patch为幅度，和sqrt(Patch_Cal)近本图比例；两者max-normalization误差相近。进一步只拟合无标签像素映射p≈clip(a*sqrt(f),0,255)：未饱和非零像素通过原点最小二乘拟合a，记录全图残差。它不是分类器训练，也不是已查明官方显示算法；用于检查最大值以外的显示饱和尺度是否存在。所有旧诊断数值仍保存，不能将拟合强度叫真值船体RCS。
