# 参考库跨采集覆盖：只读小统计

日期：2026-10-24。范围：现有64条 layer1 reference 与1741×8组已缓存 two-ref；未训练、未扩 target、未重选参考、未改主代码、未生成新图册、未操作 Git。仅新增本文及 `reference_coverage.csv`，交主流程同步。

## 结论

**现有库足以开展“不同采集支持共同确认局部证据”的小验证，不需要先扩库；但统计覆盖不是方法有效性证据。** 64条参考对应64艘不同船、35个不同 pass_group；每类8艘船，覆盖5～8个过境组。实际13,928组“查询×候选类”两参考中，13,632组跨过境，比例97.8748%；evaluation为3,803/3,880，98.0155%。全部两参考均为不同MMSI，且均与查询不同船、不同过境。

因此，当前问题不宜主要归因于“根本没有跨采集支持”。更值得检验的是：现有算法把两参考合为一个类别bag，是否允许仅凭其中一路或不同局部片段支持候选，而没有显式要求两个采集分别提供一致的判别证据。这是实现与下一轮假设的差异，不是本次已确认的失败根因。

## 需要保留的有效性缺口

1. **重复检索不是独立证据增加。** 全部1741查询反复使用同一64条库。渔船最常用的一对参考被选1120次，占64.33%；各类实际不同无序参考对仅16～25对。13,928组不是13,928套独立采集支持，也不能再乘三个旧full种子扩大证据量。
2. **两条元数据不等于两路有效图像证据。** VV两参考在body/side/end均有效。VH查询仅1538/1741有效；在这些查询对应的12,304组候选关系中，11,738组同时满足两参考有效且跨pass，占95.40%。evaluation为3210/3328，96.45%。渔船8条库只有5条有效VH，覆盖3个pass；其余类有效VH库覆盖6～7个pass。以上三个区域的可用计数一致，按既有 `mass>0` 判定，不表示细槽质量或判别性已经足够。
3. **不同采集不等于已经提取了稳定类别证据。** 参考同时改变了船只身份、位置、几何与图像响应。两路共有内容可能仍是跨类共有亮结构；必须同时检验与混淆类的区分性，不能只证明两参考一致。
4. **当前bag没有独立完成“共同确认”。** `run.regional_inputs`先各参考内部归一，再按有效参考数等权，合为支持bag；固定容量约束控制总质量，但不能自动证明同一查询局部证据被两个采集分别确认。`CASE_FINDINGS_ZH.md` 已显示候选各自优化可同时抬高错误类，本次覆盖统计没有解决这个目标问题。
5. **这是已用于开发的源划分。** evaluation485不是新的独立确认集。本报告只判断可启动性，不据此宣称泛化、分类增益或新算法有效。

## 对下一轮的最小建议

保留现有库与查询，保留参考身份，先比较“各参考分别产生判别证据后共同确认”与“现有合袋/独立平均”。共同确认必须对全部8个候选类使用同一规则，不能通过查询真标签挑同类参考，也不能用类名语义替代图像证据。缺失VH或同pass两参考不冒充跨采集双证据；可按预定规则回退单参考/旧读出，或在同一8条合法库内按可用性与不同pass约束取参考，但更换参考的收益须与聚合方式分开比较。

本轮不实施上述方法。覆盖足够启动，但算法价值仍需由匹配的简单对照、完整分类净收益及实际判别证据变化验证。
