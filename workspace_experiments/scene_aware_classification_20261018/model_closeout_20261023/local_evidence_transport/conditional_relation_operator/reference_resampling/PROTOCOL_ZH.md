# 固定模型、替换参考案例的诊断

日期：2026-10-24。以下方案在本轮计算前固定。

## 问题与下一步决策

上一轮条件关系算子能救回少量简单对照未救回的查询，但完整系统净收益为负，训练后期明显过拟合。本轮不再叠加网络，检验其关系变换是否依赖固定的64个源参考案例。

若换参考后训练收益明显消失，而身份变换的普通关系得分较稳定，下一步考虑在源端以多参考组织学习共享关系；若收益和损失不依赖参考组成，则不能把固定库当作根因，应检查类别目标与响应可预测性之间的差异。

## 固定内容

- 复用冻结的骨干、20槽位、PCA32、源划分、原始尺度输入、完整前两组件、上一轮已训练参数；本轮不训练、不选择新倍率。
- 查询：utility644、selection612、evaluation485，三个集合分别汇报；evaluation为反复开发过的队列，不称独立确认。
- 三组原完整模型配置17/29/43；可学习变换初始化实际共用17，不能称三组独立训练随机种子。
- learned/中的independent、transfer、excess，使用原源选择检查点。另检查43配置的200步终点，但只用于utility/selection，不对evaluation使用该终点。
- 原来每臂的utility身份关系RMS保持固定。不用新库重新拟合缩放或系数。相对增量仍为同一新库下的学习关系减身份关系。

## 参考库替换

从upstream/indices.npz中的fit_train1205行抽取，沿用每MMSI第一张及合法船体条件；不使用内部验证、utility、selection、evaluation案例建库。

每类8艘、总64艘。匹配原库四个组的可用性模式。按预定101、307、509、711、907抽样；尽可能排除原库MMSI，不足时只补最少数量的原参考，明确统计重叠。不为了完全无重叠改变VH覆盖或每类数量。海工类仅17艘，部分模式池小，故不同新库也会重叠，不能把五库当作五个独立数据集。

原库作为重放；五个新库全部报告，不挑最好。检查参考与三种查询角色的MMSI/过境组无交叉，比较同一查询在不同库下的分数和判定。

## 输出与原图

完整模型OA/BA、连续风险、救回/误伤、按类变化；旧/新库增量相关和符号一致；源训练与selection变化。原库重放用于发现算子、索引、冻结尺度是否与已有实现不一致，失败则修复再计算。

原图回看至少包含换库后救回、误伤、持续正确、持续错误，VV/VH分别查看，并展示该查询实际参考库中的同类与混淆类案例。只有图像事实与数值贡献对应后才解释；不把亮点命名为已证实物理机制。本轮不声称新模块成功，仅用于决定下一步算法修改。
