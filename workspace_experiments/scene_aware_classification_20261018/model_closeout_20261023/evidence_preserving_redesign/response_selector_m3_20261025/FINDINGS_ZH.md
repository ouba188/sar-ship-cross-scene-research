# 单项响应选择器：有局部救回，完整响应的迁移收益尚未成立

2026-10-25。九次训练、配对评价、固定输入诊断及六个原图案例回看完成。**保留本轮局部正信号与代码，旧M1/M2/M3 both仍为主模型；不升级成已有效的因果调节组件。**

## 1. 做了什么

冻结旧系统，以不操作和18项完整单操作为19候选。每项操作仍是VV/VH、框内/侧向/轴端、Gabor4/8/16像素尺度的描述块源均值替换，同时作用于查询与实际参考，不是原图滤波。旧96维描述中对应32维块被替换，再沿用旧核、OT对应与原分类头。

三个1101参数选择器比较：旧压缩摘要summary、全部八类分数与操作分数变化response、两者combined。相同架构和初始化，未使用输入分支置零，实际有效参数不同；不是严格有效参数相等的主张。分类风险是候选真实CE的加权期望，部署时只选一个候选，不混合分数或多个动作。源训练统计标准化，源J选择检查点，全部九个状态冻结后才打开开发端点。

仍是644源训练、612源选择、485开发查询、64源参考、每查询每类两个实际参考；开发为445船、29过境、14港。船只与过境按原协议隔离。源选择参与过旧模型选择、开发集多轮复用，不是新独立确认。

联合输入相对旧版平均BA **+0.2712个百分点**、OA **-0.0687个百分点**；相对仅响应少一例误伤。不是全无作用，也不是全面改善。

所有正确性翻转只发生在seed43。联合版1救回、2误伤；仅响应1救回、3误伤；仅摘要0救回/0误伤，但有一例从一种错误类别变成另一种。联合版救回Santos的原油轮29687，误伤Santos的散货船7085、27445，涉及3船、2过境。救回与27445误伤属于同一过境，不能视为独立场景重复。

原油轮在开发集中只有13张，散货169张。seed43原油轮召回+1/13、散货召回-2/169，故BA提高0.8136个百分点而OA下降0.2062个百分点；三种子均值再除以3。少数类收益有实际含义，但证据仍只是一艘船、一个种子的救回，不等于已建立重复性。其他六类联合版正确性未变。

按29过境做2000次配对簇bootstrap，先在查询内平均三个种子，联合版BA差95%区间[-0.0715,+1.0844]pp，OA[-0.2421,0]pp；BA只保留含八类的1742次抽样。这是本开发队列的条件性不确定度，不是独立数据或随机训练总体的保证。

## 3. 新响应到底有没有用：源端与开发端答案不同

固定seed43已选模型，不重训、不重新选检查点。将选择器输入的操作分数变化置为0，保留原八类分数、摘要及不确定性；最终仍执行所选的真实候选操作。此为输入诊断，不是新增正式方案，也不是完整的重训消融。

| 位置/模型 | 实际输入：救回/误伤 | 不看操作变化：救回/误伤 |
|---|---:|---:|
| 源选择：仅响应 | 2 / 0 | 0 / 0 |
| 源选择：联合 | 1 / 0 | 0 / 0 |
| 开发：仅响应 | 1 / 3 | 1 / 2 |
| 开发：联合 | 1 / 2 | 1 / 1 |

**可保留：本实例中，源留出上的新增救回依赖操作响应输入。** 这比“网络根本没有读到这些信息”更具体。

**未成立：开发救回由操作响应带来。** 联合版删除操作变化输入后，252/485次动作选择改变，但29687仍选择VH轴端Gabor16且仍被救回，同时少一例误伤。删除摘要时356次动作改变，联合版正确性结果仍1/2。因此，不能把开发BA增益包装成内容与干预响应协同机制已证实。中间路径确实变了，不等于净收益来自该路径。

源端依赖与开发端不依赖的差异，支持“目前学到的操作响应利用方式没有兑现可迁移净收益”这一结论。尚未确认是表示不足、源覆盖、优化预算还是决策目标造成；不把一项输入置零诊断当作唯一因果解释。

## 4. 为什么不能直接称为学会了何时不操作

step0的硬选择是0，但其softmax概率均匀，不是100%不操作。训练后的seed43三组对每张开发查询都选非零动作，联合版最大动作概率均值只有0.0721、不操作概率0.0593，选择偏好仍很浅。训练期望风险和部署硬选择有松弛差异，本轮没有通过额外训练或调温去追结果。

源训练类别加权期望CE差在联合版seed43固定100步仍为+0.000354，而硬选择训练端0救回/2误伤；源选择期望差为-0.000266，硬正确性不变。说明期望风险、单个硬动作和top1收益并不同步。1101参数和100步的本轮结果不是该方法最优上界，但也不支持立刻增加复杂度。

端点可用空间也有限且不均匀：源选择17/29/43可救回0/5/4张、可能误伤1/19/5张；开发对应0/8/4与0/6/7。后者是全部模型冻结后的事后标签枚举，不能拿来选择模型或定义有利测试范围。seed29有端点空间却没有选出有效策略，不能仅以“没有动作空间”解释失败。

## 5. 原始图像与具体证据

查看六张原生160裁剪/补零面板，VV/VH分开，包含查询及两个真实同类、两个真实混淆类参考。没有缩放船体。案例详见CASE_REVIEW_ZH.md、analysis/cases.json。

- 29687：查询和同类/混淆类参考都可见明亮细长结构，仅凭外观不能区分。VH轴端Gabor16描述替换使原油轮+0.014915、散货+0.002293，分差-0.003222到+0.009400，真实救回；不是消除了某种已识别的物理干扰。
- 7085：相同操作却令集装箱分数增加更多，散货+0.002408、集装箱+0.013036，分差从+0.004176到-0.006453。相似小幅动作对近边界样本可正可负。
- 27445：VV轴端Gabor16使散货下降、化学品上升，+0.010579到-0.032509；与救回共享过境，但响应作用不同。
- 23397：仅响应版选择VV框内Gabor8被拖轮超过；联合版选VH侧向Gabor8，保留正确判断。
- 16424：VV可见短亮船体，查询VH缺失；分差减小但仍正确。未把缺失VH补成有效图像。
- 33503：VV周围显示明显明亮，VH相对暗；分差改善约0.0959仍判错。可见背景差异不能直接命名海况或物理原因。

## 6. 成本、检查与收口

485张查询，从预计算候选核开始生成18项响应约2.02-2.17秒，约4.2-4.5ms/张额外开销；旧M3从缓存内容特征真实前向约0.39-0.40秒。选择器本身1741张约1-3ms。计时为单次阶段性测量：新响应部分尚未包括构建候选核、骨干、检测等，不能说这是完整端到端速度，也不能将训练缓存访问当部署零成本。

缓存样本对齐、18项顺序、真实单项执行、硬选择和无效掩码通过；最大完整端点重放误差5.96e-7，期望风险梯度与有限差分一致。分析阶段两个报错已修：合并统计字段重复n、历史模块修改导入路径造成analyze误导入；均在统计脚本，不影响训练和保存的预测。使用既有ClearSAR CUDA环境，无安装或系统变更。

**决定：**保留BA正信号、同类参考原图证据及源端响应依赖的结果；不以这一个救回升级完整响应选择器为正式创新模块，也不抹掉小范围作用。旧both仍为主模型。本轮新增计算尚没有得到足够的重复净收益支撑，暂不继续盲目加层或调参。

若继续，首先要解释“源端依赖响应、开发救回却不依赖响应”的差异，而不是默认下一个网络就能解决。本轮未开展新一轮训练或独立数据确认。
