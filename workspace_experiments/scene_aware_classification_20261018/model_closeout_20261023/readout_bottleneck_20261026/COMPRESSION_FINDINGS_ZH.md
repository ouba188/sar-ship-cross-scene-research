# 压缩诊断结果：有用信息没有被类别reader充分保留

2026-10-26，完成40次主拟合及16次紧凑坐标核查（各含ridge和三seed MLP）。未改原始图像、检测、骨干、旧模型或目标队列。全部源/目标预测保存后才评价目标标签。配套M2/M3支线结果另报，本文件不提前断言其结论。

## 1. 实际检验的是什么

同一native160/C4/R50的layer1特征，VV/VH分别在框内、侧向和轴端读出256维均值。现有源端reader_layer1权重为四类×512，按极化分为W_p，每个W_p实际秩为3。

若V_p为W_p行空间的正交基，则：

`x_keep = (x @ V_p.T) @ V_p`

`x_drop = x - x_keep`

实际全部源/目标样本验证：W_p在x_keep上的响应与原x相同，W_p在x_drop上的响应为零，最大误差约1.2e-12。原始区域输入与上一轮完全相同，direct各模型源/目标预测严格重放。这里的3维不是bug：四类线性分数可能仅有3个独立类别对比方向；需要检验它是否足够，而不是因维数小先判错。

direct、keep、drop、同秩PCA都重建成相同输入宽度，再用同一个128隐层MLP、200步、源fit/fit_validation、种子17/29/43。各臂独立的源端标准化和恒定维屏蔽；名义参数量和初始化相同，实际有效秩并不同，不能称统计容量完全相同。

首批低秩重建效果差后，补做等价紧凑坐标 `x @ V_p.T`；这不改变保留的信息，但改变参数化及标准化/正则化。该对照源模型较小，单列，不用它覆盖主对照。

## 3. 目前可以确认到哪一步

1. **当前源reader不是区域分类信息的充分表示。** 在现有数据、读出族与训练预算下，被它线性消去的部分仍能支撑相当水平的跨数据集分类。不能再默认类别响应已经囊括全部有用信息。
2. **参数化影响了一部分结果，但解释不了全部差距。** 紧凑坐标比冗余重建更好，因此第一轮不能把所有下降都归为信息损失；紧凑坐标仍明显弱于direct/正交补，支持实际信息缺口。
3. **换成PCA三个方向也不够。** 它的BA更好，但仍未接近完整区域特征，说明既可能有方向选择问题，也有低秩表示不充分的问题；不能说只需更换3个方向即可修复。
4. **不是仅换一个普通大头就能补回来。** 实际M2双向统计等摘要接普通MLP仍弱于direct。这支持检查摘要的信息供给，但该对照的头宽度/参数量不同，也没有上游base，因此不能当作完整M2优劣的唯一证据。

## 4. 代码中发现的具体设计限制

`oss1_m123_replication_20261026/train_frontend.py`的fit_base将整chip有效足迹内的global1/global3均值用于fit_reader（约277–278行），fit_reader再做源PCA128与四类ridge，合成线性W（约197–225行）。随后同一W用于局部响应和区域摘要。

因此当前reader学习的是“哪些特征方向适合全局均值分类”，不是直接学习“各局部区域需要保留什么信息”。这是已核实的训练/使用方式差异，不是程序跑错。它可能解释局部区域信息保留不足，但尚未单独比较全局训练reader与区域配套训练reader，不能称已证实唯一根因。

此外，M1是layer3，M3另有局部描述及基础路径；本轮针对layer1类别reader的结果，不能外推为整套模型都只剩3维，或全部其他信息都已消失。
