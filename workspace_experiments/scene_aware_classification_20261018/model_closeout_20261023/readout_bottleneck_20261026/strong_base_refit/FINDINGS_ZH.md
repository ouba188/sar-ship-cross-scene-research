# 强基础配套重拟合：M2与固定匹配器M3读出

2026-10-26。本独立支线已完成，不再扩实验；仅写本目录，未修改旧代码、主代理根目录或Git。

## 结论

**换用直接区域MLP后，配套重训的修正能有小幅净收益，但没有稳定地保住所有原有优势。问题不能只归咎于“没有配套训练”，也不能归咎于数据不可识别。** 两方向体现不同类别权衡，M2与M3需要分开判断。

1. OSS1→OSS2：裸强基础OA/BA=53.7781/51.0819；+M2=53.6751/51.5024；再加M3=54.0869/51.3896。完整配套修正相对裸基础平均+0.3088/+0.3077个百分点，三种子并非全赢。
2. OSS2→OSS1：裸基础60.0796/50.8147；M2三种子均选择零步；再加M3=59.2110/51.7085，即OA -0.8686、BA +0.8938个百分点。不是全面失效，而是多数类与少数类取舍改变。
3. 旧M1→M2重放：两源×三种子×源/跨域共12项，最大分数误差0，预测完全相同。本支线M2实现没有偏离原s12。
4. M3所有base依赖字段已重算，零步恒等检查全部通过。不能把这些结果解释为误用了旧基础的分数特征。

## 实验口径

- 强base严格复用 `paper_evidence_completion_20261026/classical_fit_only/oss*/source_predictions.npz` 与 `cross_predictions.npz` 的 `regional_mlp_seed17/29/43`。源fit_train训练、fit_validation选择，不是pooled版本。
- 对照base为 `public_m123_cross_dataset_20261026/normalization_repair_20261026` 中corrected M1。
- M2沿用原regional_raw的69维输入、69→12→1头，fit_train/fit_validation，200步，AdamW .003/.01，5步检查，精确J=(OA+BA)/2，严格改善才替换，允许零步。标准化仅fit_train拟合，严格恒定维置零，本批输入没有恒定列。
- M3复用各源各seed已训练的PairMetric、原32源bank、每类两个实际检索参考和local匹配缓存；**匹配器、检索和参考不变，仅配套重训读出，不是整个M3 metric重训。** 匹配器原来针对旧基础学习，仍可能约束新基础下的上限。
- 新M2分数重新构造15维local_raw（12匹配统计+3分数背景），utility_train拟合新scaler，重训JointHead、VV头、centered VH头各200步；selection选择。B的alpha仍0至1、步长0.1，源端J选择及原平局规则。
- 185维frequency gate的前11维按新base、新VV/VH修正重算；后174维空间/频域描述沿用固定图像和参考的既有内容。gate scaler仅utility_train拟合，100步。没有新增空间gate候选或超参数搜索。
- 全部12组（两源×三seed×两base）源/跨域预测保存后才计算目标指标。源evaluation标签在训练入口置-1；跨数据集训练入口不加载class_id。源训练预测不是OOF，保留既有阶段组织，不隐瞒这一限制。
- CPU2线程；训练约25秒，不含此前提特征/匹配缓存。此前首次启动因pandas数组只读停止，改为显式copy后正式运行；没有因此改变实验设定或查看目标结果调参。

## 原图证据与边界

8张native VV/VH面板已逐张实际查看，详见CASE_REVIEW_ZH.md及cases.json，含真实源参考、图像路径和裁补记录。

- 正向救回2296和误伤149都主要在M2发生，不应把最终翻转一律算给M3。
- 反向seed17 M2=0：0号散货被VV校正救回；976号普通货被VV误伤，能够明确将变化定位到M3读出。
- 参考与查询均出现跨类别共享的短亮条/端点响应，外观不支持“某一模式必属于某船型”。本轮没有像素干预，不能证明具体亮点引起了某次修正。
- 这些历史四分类队列不是独立新盲测；未覆盖24港、F_0921、其他折，未改变参考库或重训PairMetric。本轮不宣布新主模型取代现有方案。

**本支线完成的判别是：配套读出训练可利用一部分强基础之外的证据，但不足以消除跨域类别权衡和极化选择失配；主线压缩诊断仍需独立解释哪些输入信息在进入类别响应时丢失。** 不继续扩展。
