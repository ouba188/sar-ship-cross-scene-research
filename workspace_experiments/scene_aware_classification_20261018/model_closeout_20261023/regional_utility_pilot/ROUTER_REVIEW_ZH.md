# Router 独立实现与设计审阅

日期：2026-10-23。范围仅 `run_router.py` 和上层 `THIRD_COMPONENT_PLAN_ZH.md`；上游四角色 source-only 整链排除由另一代理负责，本次不重复审计。只运行无拟合的最小合成检查，没有读取真实训练样本训练、修改脚本或操作 Git。

## 结论

**未发现阻塞执行的轴、标签广播、源选点或共同logit偏移错误。** 可以按冻结协议开展 pilot，但有一个直接影响机制结论的目标差异：辅助监督是单策略概率的逐类Brier改善，实际操作是逐类中心化logit融合；前者不是后者的真实采用效用。这个差异不等于方法必然无效，CE可能协调二者，但不能用效用回归准确来替代最终融合有效的证据。

另须明确：utility与CE对照同时改变了前20步训练目标；0步是等权融合而非base；三seed不是三份独立样本。下面给出可直接修正的解释范围，不要求为这些已知边界再加实验。

## 1. 必须区分的效用任务

位置：`run_router.py:27` 的 `utilities`，`:43` 的 `blend`，`:163` 的目标缩放，以及 `:200` 的20步纯效用warm-up。

代码准确实现计划中的

`u[k,c] = (p[0,c] - y[c])² - (p[k,c] - y[c])²`。

但实际输出是 `s[c] = sum_k w[c,k] * z[k,c]`，其中 `z[k]` 在各策略内部按类别去均值，最终还对拼合后的八类分数做softmax。改变一个类别的策略会改变全体归一化概率。因此 `u[k,c]` 不是“把融合器的类别c切换到策略k”的Brier改善。由于 `z[k,c] = log(p[k,c]) - mean_c(log(p[k,c]))`，不同策略的整组概率分布也会影响该类的中心化logit，不能从更小的单类概率误差推导更有利的拼合分数。

### 已执行的最小反例

只用一个合成八类观测，真类0，无训练，概率均合法且和为1：

```text
p_base = [0.4, 0.2, 0.4/6, 0.4/6, 0.4/6, 0.4/6, 0.4/6, 0.4/6]
p_body = [0.3, 0.1, 0.599995, 0.000001, 0.000001, 0.000001, 0.000001, 0.000001]
p_full = p_base
scores = log(stack([p_base, p_body, p_full]))
u = utilities(scores, [0])
u_scale = sqrt(mean(u[..., 1:]**2)) = 0.0949717892
weights = softmax(u / u_scale, axis=strategy)
```

直接把精确 `u/u_scale` 当成网络输出，走原 `blend`：

|输出|预测|真类减类1分差|最终Brier|
|---|---:|---:|---:|
|base|0|不作为该项比较|0.426667|
|等权融合|0|+0.828302|0.307957|
|精确效用预测后按原接口融合|1|-1.053233|1.069365|

此时 `utility_mse=0`。所以问题不仅是Brier代理不保证OA，而是**拟合这里的Brier代理，也不保证最终融合Brier改善**。这不是实际源数据退化的证据，不据此否定pilot；也不把合成反例当作真实发生比例。

**直接可做的修正：** 保留已冻结实现和原始结果，将机制表述明确为“单策略逐类Brier改善的辅助监督 + 最终融合CE”，把 `utility_mse/proxy_regret` 限定为代理任务诊断。不得把 `estimated` 或 `w` 宣称为已校准的实际融合收益、独立因果效用。若当前目标一定要求监督与采用操作严格同义，则必须重新定义监督对象，并重新冻结协议；不能仅将logit改成概率融合就宣称解决，因为逐类概率拼接仍有归一化耦合。本次不提出额外网格或擅改融合接口。

## 2. CE配对：实现公平，但结论针对整个训练流程

`run_router.py:180` 两臂相同输入、源train scaler、网络、seed初始化、AdamW和200步预算；代码检查初始state逐值相同。`class_weights` 使分类损失等于0.5普通CE加0.5本训练集出现类别的均衡CE；效用项也使用相同样本权重。没有发现标签权重轴错误。

`run_router.py:200` 明确是：

- CE-only：200步CE。
- utility：前20步只优化aux，后180步CE+0.1aux。

这是计划中“先效用学习、再联合约束”的实现，并非偷偷增加训练预算。但若utility胜出，能支持的是**效用预热加联合监督这一整体流程**，不能单独声称lambda=0.1辅助项本身带来全部收益；若失利，也未区分预热与后续联合目标各自影响。当前不必增臂，只需报告 `warmup_steps=20`，保留现有对照与曲线。

CE-only的网络输出未被训练成数值效用，其utility MSE不应与utility臂作为对称的主要胜负指标；最终OA/BA/J/Brier和固定融合对照才是共同任务结果。

## 3. 已确认正确的实现

- **策略/类别轴和标签：** `scores[N,3,8]`，`np.eye(8)[y,None,:]` 为 `[N,1,8]`，得到的效用经moveaxis为 `[N,8,3]`，strategy0恒0。独立逐i/c/k标量公式与 `utilities` 最大误差0；不是误用同一标签或沿类别做策略softmax。
- **输入与融合：** `own` 和 `competitor` 均 `[N,8,3]`，竞争类来自最高非该类分数，不用真值挑选。权重softmax在最后的策略轴；三策略one-hot权重返回对应中心化策略分数。每类融合为该类三个中心化logit的凸组合，不是概率凸混合。
- **共同logit偏移：** 每策略独立类公共偏移在构造score输入和融合前已去掉。合成检查输入最大偏差 `4.72e-15`，融合最大偏差 `1.89e-15`。这里固定regional输入以隔离score接口；上游regional字段的生成语义不在本次重复审计范围内。Brier标签自身通过softmax也不受这种偏移影响。
- **效用缩放：** `u_scale` 仅由utility_train标签计算，训练目标除该尺度、诊断乘回尺度一致。它同时决定效用预测进入策略softmax时的量级，不能解释成与门控行为无关的纯报告单位变换；当前是固定源规则，未见测试调温度。
- **分角色使用：** scaler与u_scale只fit utility_train；固定融合候选、两学习头checkpoint只看selection的精确J；严格 `>` 保留最早平局。已定向核对主流程最新顺序修订：`:221` 的每臂评价跳过evaluation，`:233` 起在本seed两臂选点完成后才统一计算静态指标/oracle和学习模型evaluation结果。evaluation不参与梯度、候选权重或checkpoint选择。旧版提前计算但不使用这些指标也不构成已证实的选模泄漏；新版顺序更明确，不据此重复上游审计。
- **角色与身份：** 本脚本只消费上游提供的utility_train/selection/evaluation三种留出输出，第四个策略拟合角色在上游。入口检查行索引、role一致、instance唯一，并检查这三角色的MMSI/pass不交叉。本次不由这些局部检查宣称已经独立证明整栈排除。

## 4. 零步、评价与样本单位

**0步是equal，不是base。** `Router.forward` 把base效用固定0，同时末层输出0，于是三策略权重都是1/3。最小合成验证，torch零头输出与双精度equal的最大差为 `9.24e-8`（浮点量级）；与base最大差为 `1.6465`。若选0步，必须报告“保留等权融合”，不能沿用旧区域实验“退回B、无融合增益”的语句。只要候选不同，0步相对base也可能有收益或损失。

`fixed_candidates` 是等权先列、再列步长0.25的15个全局权重，共16项；只在selection选最早J最佳。三单策略、equal、fixed都有独立报告，便于区分普通融合与可学习路由。

`opportunity.oracle_OA` 是“任一完整候选判对”的不可部署单策略选择上界，不是逐类融合器的严格上界；后者可能在三个策略均错时通过不同类权重得到正确结果。它可衡量候选分歧，不能用来封顶融合器。代码没有把oracle用于训练/选择，此处仅需名称说明。

三seed共享同一 `table.csv`，每个npz又与相同table索引和role对齐，因此是同一观测集的三次拟合/上游预测，不是3N独立船。当前metrics逐seed保存，没有代码内的伪扩样本统计；后续结论应分别列seed并按实际船/过境识别单位，不把均值当三次独立数据复制。BA/J按每角色实际出现的类别计算，`metrics.classes`已保存；若角色缺类，不能把它写成完整八类均衡指标。这一类别覆盖由上游清点负责，本次不重复大范围统计。

## 修正核对补记：单坐标替换效用

主流程在任何真实router训练前修正 `utilities`。以上审阅和旧反例保留为修正前记录；不应继续把旧标签定义归给新版实现。

已定向读取新版函数：令各策略中心化logit为 `z[k,c]`，固定背景 `v=mean_k(z[k])`。对每个类别c、策略k，复制完整八类v，只将第c坐标替换为 `z[k,c]`，对所得八类向量做softmax，再计算完整Brier `L[k,c]`；返回 `u[k,c]=L[0,c]-L[k,c]`。代码的 `[N,8,3,8]` 张量、单坐标赋值及标签广播符合该定义，**参照是同一背景下替换为base坐标的风险，不是未经替换的v风险，也不是完整base向量的风险**。

只重放上文原合成例，独立逐c/k复制v、替换一个坐标、计算完整八类Brier，与新版 `utilities` 最大误差0，base效用严格0。没有训练或再搜反例。

|同一合成例|修正前预测 / 最终Brier|修正后预测 / 最终Brier|
|---|---:|---:|
|等权融合|0 / 0.307957|0 / 0.307957|
|精确标签经 `softmax(u/u_scale)` 后融合|1 / 1.069365|0 / 0.000113760|
|逐类标签argmax策略拼合|1 / 1.980554|0 / 0.000001655|

新版该例 `u_scale=0.6709406211`；body对真类0的单坐标效用为 `+1.143167`，对错误类1/2分别为 `-1.655766/-1.775989`。这修正了原例中“单策略概率误差较好却采用了不利中心化logit”的标签方向。精确标签的soft融合真类减类1分差为 `+5.212518`。

这里的oracle使用合成真值构造标签，只用于核对接口，不是可部署结果或真实数据提升。新版标签现在确实衡量固定等权背景下的单坐标介入，仍不承诺多类别同时软融合后的总风险可加；最终CE约束真实融合决策。这个剩余边界已被新定义明确接受，不构成本次继续扩大审计或中止pilot的理由。无新增实现阻塞。

### 数值链条与结论边界

对11556的原始前向，将第一层仿射结果按floor列与其余列作精确加法分解，没有删除输入或重新算替代模型：floor列贡献最大绝对值分别为41535 / 50045 / 50628，其余列加bias仅34.90 / 8.30 / 5.69。该两列源训练输入近0，因此没有提供覆盖降低方向的有效学习支持；留出真实变化经极小分母放大后驱动隐藏层大幅外推。这个数值传播路径与异常效用输出、误差集中于同一观测一致，足以定位当前MSE爆大的主要来源。

该观测三seed的策略权重均饱和到0/1：seed17/29八类都偏向full，seed43八类都偏向body。三种候选本来就都判错（seed17类4、seed29类5、seed43类1），router也分别给出相同错类。因此**本次MSE异常不能直接用来解释全部OA/BA差异，也没有证明修复后就能救回这个样本**。CE-only未受效用回归监督，不以其更大MSE判定其任务更差。

保留原始正负结果。已定位的是“源近常量coverage按极小std缩放 + 留出覆盖变化”的接口数值问题，不等同区域效用方向无效或一般跨域失败。后续如修正，应按源端可确定规则处理这些列并对CE/utility共同实施；本次没有选择修正规则、设置新阈值、修改代码或重训。
