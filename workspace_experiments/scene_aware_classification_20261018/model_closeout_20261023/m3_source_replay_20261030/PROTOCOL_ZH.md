# M3源覆盖与更新方向小验证

目标：不改M1/M2及骨干结构，检验M3更新是否受有限适配样本覆盖限制；不是假定稀有类或大权重一定有害。

先在现有完整模型seed17端点，测自建开发集与OSS2的M3值投影、输出和增益参数梯度。逐类计算适配源、较广source_fit、开发集的平均CE梯度；source_fit按船等权，随后各类等权。比较方向和范数。开发标签仅作诊断，不用于反向更新。它不是实际Adam更新，也不是证明某类导致退化。

若存在源覆盖差异及更新冲突，再试同预算训练：adapt_only与source_mix。两臂从同一完整模型开始，只更新原M3的project/output/gain，保留原比较器、原参考库及模型其他部分。两臂使用相同类别序列，每批16条中前8条完全相同；后8条分别来自source_adapt或source_fit，按类别、船只、观测三级抽样。两臂相同CE+0.1正确预测保持KL，AdamW 1e-4、weight_decay=.01，6*ceil(adapt_count/16)步。不因开发结果调整学习率、混合比例或步数。本轮不引入源中心化，以隔离训练覆盖问题。

开发判断必须同时对现有完整模型与同预算续训对照报告OA/BA及概率风险，按训练顺序配对。初始seed17用于筛选；有收益路径再扩17/29/43。仅开发数据有改善不等于完整目标达成。最终测试不用于选参数。出现负结果保留，不无限扫参。

训练后查看原始VV/VH持续判对、持续判错、救回、误伤及实际参考案例；没有某状态明确记录。核实不训练的权重/缓冲区不变、保存重载一致及原始chip输入与缓存一致。每个检查对应具体接入/存储风险，不重复全量审计。

seed17之后追加一个无需训练的辨别性对照：将adapt_only相对原模型的M3参数变化乘以source_mix变化范数/自身变化范数，再评价开发集。不使用标签选择倍率，仅匹配全局参数变化大小。它用于检验混合训练收益是否可以被较小更新复现，不是新候选，也不证明逐层更新完全匹配。三训练顺序固定扩围，不据结果调学习率/比例。
