# 源恒零特征修复：完整模型复现结果

2026-10-26。**修复值得保留：既消除了已定位的数值放大，又在OSS1→OSS2上取得净分类收益。修复后B相对旧both的优势保住并扩大，但频域额外收益仍很小。** 这是标准化/输入可学习性修复，不是新增因果模块，也不作为新的算法创新来包装。

## 1. 改了哪里，为什么这样改

源训练没有变化过的输入维度，无法通过该维输入学习其变化与类别之间的关系。旧邻域D把这些维度除以1e-5；换数据集后它们突然激活，已有权重就可能把它们大幅放大。

只取源fit_train中可用极化的centered特征，逐维计算取值范围，**严格等于0才屏蔽**。OSS1为VV10维/VH8维，OSS2为VV6维/VH6维，均与上一轮恒零证据相符。没有使用目标标签，没有选择阈值，没有屏蔽低但非零方差特征。维度、来源及常量值存为两个source_constant_dimensions.csv。

源checkpoint、标尺、PCA、温度、图像、检测框、32源参考、检索及比例完全不变。修复发生在D标准化输入，随后实际重算D、校准T、M1、M2及完整M3四臂。M3的joint/polar残差及gate均含base依赖，不能沿用旧delta或旧gate再加新base，本轮没有这样简化。旧local匹配与参考应不变，运行时已验证一致。

实现：共享transfer.py增加可选neighborhood_active参数，默认不传时仍复现旧结果；run_repair.py在源端导出mask后传入。新结果均位于本目录，父目录原始冻结结果未改。它是已暴露数据上的定向修复，不是独立盲测，也没有重新训练下游参数。

## 2. 数值失稳是否解决

OSS1→OSS2 seed17全1619条，最大类别分数绝对值：

|阶段|原来|修复后|大于100的查询数 原来→修复|
|---|---:|---:|---:|
|U=A+D|1383.9871|8.5014|68→0|
|M1+M2，s12|3753.8936|40.2802|74→0|
|旧both最终|1658.8615|24.7762|68→0|

这闭合了“源恒零维度→目标激活→极小标准差放大→D异常→下游放大”的计算链。它没有证明这些激活是纯噪声，或者某个海面物理机制；只是当前源训练未学会使用这种变化。未更改仍有变化的低方差维度，也不将所有剩余错误归因于标准化。

## 3. 完整分类收益

四分类、目标1619条/1347船/27过境，三个冻结源训练种子17/29/43。均值OA/BA单位%。

|方案|原OA|修复OA|原BA|修复BA|原NLL|修复NLL|修复Brier|
|---|---:|---:|---:|---:|---:|---:|---:|
|旧both|48.8573|49.0014|45.2720|45.3139|10.1682|1.4348|0.685456|
|B固定|49.9691|50.4632|46.2073|46.8130|3.8436|1.4141|0.677475|
|B+空间|49.9691|50.4632|46.2073|46.8130|3.8436|1.4141|0.677475|
|B+空间-频域|50.0103|50.5044|46.2099|46.8156|3.8351|1.4056|0.675283|

B的修复净收益为**+0.4941 OA/+0.6057 BA pp**。不是每种子都变化：只有seed17的D被源端选择为非零，其B救回35条、误伤11条，净+24；29/43所有最终四臂分数完全不变。旧both在17救回21/误伤14，净+7。

seed17 B的类别分解：散货9救回/0误伤，普通货0/0，化学品23/0，集装箱3/11。收益主要来自散货和化学品，集装箱有损失，不能写成各类均衡改善。全部80条预测翻转中，26条属于错误类别之间的变化，未计为救回。

以27个目标过境做配对bootstrap、每查询先平均三个冻结种子：B修复的OA95%区间[0.0935,0.9690]pp、BA[0.2129,0.9633]；旧both对应区间跨零。这是当前采集与冻结模型条件下的区间，不把三个种子的同一查询或同船重复观测当独立新增证据。

## 4. 修复后M3比较有没有改变

修复后的B相对修复后的旧both：**+1.4618 OA/+1.4990 BA pp**；对应过境bootstrap区间OA[0.4768,2.6470]、BA[0.2856,2.9715]。seed17救回168/误伤114，29为90/110，43为123/86。因此，不是仅靠原来的异常大分数才产生B平均优势，但仍不要求或宣称每次训练都胜出。

频域对B仍只有**+0.0412 OA/+0.0027 BA pp**，其差异来自未受修复影响的seed43（12救回/10误伤）；17门控零步，修复前后frequency都与B相同。空间门两源全零步。故这轮新增收益属于源恒零输入修复，不归给频域、新VH或动态选择。

修复后累计基础OA/BA=47.5190/44.6986，+M1=49.3515/46.2068，+M2=48.1573/45.4366。M1保有平均分类收益，M2在这个迁移方向仍下降；B后端改善不能掩盖此边界。

## 5. 源端与反向迁移

源fit全部阶段及最终四臂分数最大误差为0，两公开集均如此；源fit_validation与原目标evaluation也没有指标变化。

OSS1 source seed17的utility_train和selection存在源fit未激活维度，因此受到影响：B在utility净救回1条（OA+0.8197pp），selection净救回1条（+0.5348pp）；NLL/Brier也降低。其余源种子、OSS2所有源角色不变。没有利用修复后的selection重新挑checkpoint、比例或训练轮数，保留原冻结协议。后续若从头重训，应在生成utility训练输入前应用同一个源规则，而不能继续混用旧失稳输入。

OSS2→OSS1，921条/742船/21过境：三种子最终四臂分数与原结果完全相同。OSS2源D均选零步，此修复没有影响。旧both61.2378/52.0941，B/空间61.1654/50.6127，频域61.0206/50.7004。反向BA下降仍然存在，不能声称本修复解决所有跨域退化。

## 7. 保留决定与复现

保留源恒零维度屏蔽，作为这套公开集冻结推理的标准化修复。它低成本、源端定义，解决了可复现的输入放大问题，并带来任务范围内净收益。保留B候选和原旧both对照；空间-频域仍为小幅、有边界的候选，不提高其创新性评级。

代码入口run_repair.py；共享transfer.py默认旧行为保留。analyze_repair.py生成逐阶段/类别/过境前后对比、bootstrap和原图面板；原图结论在本报告，原路径和参考在各cases.json。启动时发现源scores缓存没有axis/A/U，已改为原函数重算并与已有M1/M2缓存核对，独立审阅确认已解决；不是修改训练或挑结果。

本轮未改24港独立工程的默认推理或权重，未做新训练或新的检测实验。下一轮若继续，优先在修复后的基线上研究尚存的类别/参考证据问题，而不是反复处理已消除的爆值。原结果、修复结果和负案例均保留并同步GitHub。
