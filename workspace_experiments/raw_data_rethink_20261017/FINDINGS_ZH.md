# 从原始裁片重新设计船体—邻域关系

日期：2026-10-17。状态：图像、数据来源核查与文献方法阅读完成；没有新训练，没有替换主模型。本报告中的新结构是待验证设计，不是已获得收益的模块。

## 结论先说

用户提出的方向应保留：**向外取信息要参考船轴，同时参考雷达观测角度。** 但不能简化为把旧环带转一个角度，或者给全部区域乘同一个角度权重。

这次从实际输入看到的更具体问题是：现有流程把不同裁片尺度、不同方向和不同可见范围的邻域，压缩成同名区域的特征；这些区域未必具有相同空间含义。合理的新假设是：先明确局部响应相对船轴及雷达方向的位置，再检验这种组织能否提高跨采集的类别判别。**不预设邻域是噪声，不预设同类船具有同一种邻域，也不预设角度必定有用。**

## 2. 图像和来源约束

### 2.1 原尺寸PNG不等于原始雷达数值

追溯到的生产链是measurement TIFF、重投影、场景/极化灰度拉伸、分块、动态裁片PNG，再进入网络缩放。当前检查的PNG已拉伸，不是标定的sigma0，也不是dB。相关实现为：

- `E:/s1_geocoder_src/s1_geocoder_batch_skip.py`：重投影、分位数拉伸、8bit输出。
- `E:/临时会话/cloud_sentinel1_pipeline.py`：另一条重投影与直方图拉伸实现。
- `E:/临时会话/build_v5_context_chips.py`：按目标长度动态取窗，不是在这里重新做辐射标定。

历史样本缺少逐场景拉伸边界和实现版本的完整对应，因此不能把脚本默认参数当作所有样本已核实参数。追溯到的拉伸前TIFF路径、派生int16候选和部分归档路径目前未能本地访问；这不等于全机或远端一定没有。

目标查询框内共416240个像素，44465个等于255，占10.68%；54460个大于等于200，其中81.65%等于255。**后一个比例的分母是高亮像素，不是全部船体像素。** 此结果说明当前显示高亮值有明显顶端堆积，不能据此恢复真实散射强度或归因于某个物理机制。

### 2.3 环带有方向、尺度和可见范围的问题

现有区域在56格点特征图上膨胀2/8/16次，SciPy默认十字连接；这不是以米定义的邻域，也不是沿船长、船宽分别设计的邻域。

| 查询集合 | 数量 | 远环带平均可见比例 | 有截断的样本比例 | 可见不足一半 |
|---|---:|---:|---:|---:|
| 源训练 | 279 | 83.73% | 82.80% | 1.08% |
| 源选择 | 168 | 92.73% | 56.55% | 0% |
| 目标查询 | 226 | 87.48% | 63.27% | 1.33% |

这不是“多数远环带都看不见”：目标平均仍可见87.48%。但固定名称的区域覆盖量并不完全一致，读取时需要记录有效面积，不能把画面外当成黑水面。

在目标查询中，贴框、近邻、远邻的高亮像素中，与框内高亮8连通的比例分别为75.97%、48.89%、28.26%。它们只是显示阈值200下的连通统计，**不能分别命名成船体、尾迹、杂波**。图上能看到贴近框的延伸响应，也能看到远处孤立亮点；应保留位置和连接关系来检验，不能混成一个背景均值。

### 2.4 现有角度门控还存在训练覆盖限制

以已有geometry sidecar统计：源训练查询279张中49张ship_valid，源选择查询168张全部标为no_existing_axis，目标查询226张中43张ship_valid。缺少历史轴记录不等于图像没有船轴。

源选择集合在这一门控下不能有效挑选“激活空间组件”的能力。这是目前任务组织的具体限制，不能直接据此认定模块无效，也不能在目标查询上选择新几何方案。下一轮需在源端构造具有实际角度覆盖的独立选择任务；源端无足够任务时预先固定训练步数，并单独报告覆盖。

## 4. 改成怎样的设计假设

### 4.1 两套坐标，不是两个角度简单相加

用户补充确认：船体轴向从当前SAR图像检测/估计，不依赖AIS报告的航向。AIS仍可用于已有的身份关联、类别标注和分组排除，但不作为本组件的方向真值。优先使用已修正角度约定的OBB及框内响应核查轴线；检测框角度是候选图像轴，不默认等于真实航向。轴向不确定时保留置信度，不强定船头船尾。

区域设计进一步修正：**船轴与雷达几何共同参与采样区域的定义和局部信息组织，不是先仅按船轴确定全部区域，再在末端补雷达角度。** 候选采样布局同时保留沿船轴的纵横邻域与沿可靠雷达距离轴的邻域，按二者相对方向组织重叠位置；恢复可靠方位向后再加入相应布局。入射角作为布局分配/聚合的条件候选，不被误作平面旋转角，也不预设未经验证的“角度越大就取越远”规则。控制采样总量并记录重叠覆盖，避免把重复取样误当新证据。

对邻域位置p和目标中心c，先在统一坐标系中定义：

`u = dot(p-c, ship_axis) / L`

`v = dot(p-c, ship_transverse) / W`

L/W最初是检测到的图像响应尺度，不冒称真实船长船宽。保留实际像素间距、裁窗尺度与有效覆盖，避免仅归一化后又丢掉尺度信息。尺度下限依照有效分辨单元及源端统计确定，不从目标分类成绩调参。

沿u轴两端、沿v轴两侧分别扩展，允许纵横覆盖不同；不是先把船转正，再做原来同样的膨胀。没有可靠航向时只称“船轴两端”，不强定船头船尾；需要对180度轴符号翻转作一致处理。

同时为这些局部位置保留雷达地面距离向的投影坐标，以及船轴相对该方向的角度alpha；入射角i单独编码。当前缓存雷达轴由产品地理定位网格的距离向估计得到，是**无向地面距离轴代理**，不是已经恢复的完整三维视线或飞行航向。若后续需要方位向、有向近远侧，必须从对应产品几何另行恢复，不能给现有代理改名冒充。

当只有无向轴时，相对角用cos(2alpha)、sin(2alpha)等周期编码，不把轴翻转当成条件突变。不同坐标系先作投影/仿射转换，不能直接拿地理方位角减图像像素角。

### 4.2 角度在局部聚合前参与，而非最后广播一个门

候选局部单元包含：局部响应、船轴相对位置、雷达方向相对位置、尺度、可见面积、角度有效性。用这些信息组织局部匹配/聚合，再得到每张chip的描述符。

关键不是预设“这个角度就该多看船尾”，而是检验：**同样出现在框外的响应，按其相对位置及观测条件区分后，是否比全混在一起更有分类价值。** 图像坐标保留为基线，几何不可用时回退，而不是一律删除样本。先不要求网络强制去除这些变化。

初版不采用任意可变形采样和无约束大注意力网。先使有明确含义的区域与位置编码可视化、可替换，保持与现有数据量相称的参数规模。复杂度由实际失败点决定，不由模块名称决定。

### 4.3 接入完整流程

`原尺寸裁片 -> 图像检测船轴 + 产品雷达几何 -> 每极化可靠坐标/覆盖 -> 船轴与雷达几何联合组织的局部单元 -> 条件聚合 -> 共享描述符h -> 支持核补充 -> 重求支持系数 -> 原完整分类输出`

基础分支、原有专家核和融合协议先冻结。延用共享描述符构成的Gram补充项，使SS和QS来自同一表示；不分别预测两个不一致的核矩阵。不恢复已弃用的5%交接，也不把局部检索改善直接算成完整分类收益。

## 5. 最小、可归因的下一轮

先固定合法源训练数据、实际支持集合、查询集合与模型宽度，保留同采集对照但不以“同采集也涨”为否决条件。

1. **坐标是否有用：** 同一批采样局部单元、同等读出容量，比较图像位置、船轴位置、船轴加雷达位置、再加入射角。保持采样内容不变，回答增益是否来自几何组织。
2. **联合取样是否有用：** 固定读出方式，比较原环带、仅沿船轴纵横扩展、船轴与雷达几何联合组织；控制总有效采样量/单元数及相同几何可用性，另报告实际范围差异。回答雷达是否真正改善区域选择，以及是不是只因多看了图像。第1项的固定内容对照用于隔离位置编码作用，不代替这里的联合采样主候选。
3. **雷达数值还是可用性标记：** 真角度对照相同有效性掩码下的固定角度；诊断可在源端按类别/尺度匹配交换角度。交换仅用于归因，不参与目标模型选择。
4. **最终在哪里生效：** 记录同类跨船检索、实际支持核变化、完整OA/BA及救回/改错；按相对角度、尺度、覆盖、类别分层。以船/采集为统计单元处理重复出现，支持抽样与训练种子分开报告。

本轮不进行上述训练。数据与图像已给出合理可检验的收益路径，可以进入这组针对性实验，但当前证据尚不能断言“船轴加雷达必定涨点”，也未证明现有微小收益来自这一机制。
