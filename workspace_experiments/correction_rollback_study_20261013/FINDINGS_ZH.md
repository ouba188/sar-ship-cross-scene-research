# 错误回退的计算路径与数据依据

2026-10-13。本轮主训练、冻结预测、评价与定位干预已完成；支持交互详见 `SUPPORT_FINDINGS_ZH.md`。没有替换主模型。

## 结论

这轮不是再找一个能解释平均分的说法，而是定位到选择器实际如何否决有效修正：在桑托斯散货的错退样本中，支持类别计数项是最大的平均负logit项；在洛杉矶原油中，支持OOF项与计数项共同压低接受分数。将这些路径中和会找回大量原有救回，验证了其计算作用。

更深的数据解释已经出现：在“改判到支持更多的类别”这一组中，桑托斯目标事件按样本数约77.06%是救回，按完整query的BA权重却仅40.51%是救回；源训练也呈现同方向的OA/BA反转。因此，计数惩罚并非莫名其妙或已证明学错，它有保护BA的实际依据，却会牺牲多数类的一部分正确样本。

直接删掉这些统计能缓解OA损失，却损害BA；新增改判类别身份也没有明显改善。优先问题是**能否在这组利益冲突内部区分具体好修正和坏修正**，而非再增加类别标签编码或全局关掉支持统计。

本结论定位的是模型决策路径，尚未声称识别了物理因果或所有跨港失败的唯一原因。原BA选择器在巴生的收益继续保留。

## 本轮做了什么

1. 保持expanded源训练任务和44个B16评价单元不变。源数据1296观测/525艘船，源事件1317次暴露，不把重复context与支持抽样当独立样本。
2. 分解原16维选择器的冻结logit：置信度、基础分支一致性、支持OOF、角色支持计数、支持覆盖/总体OOF统计。逐事件加回原logit，逐任务加回原BA得失。
3. 按有序raw预测类别到initial预测类别统计源事件覆盖，跟踪目标救回与误伤。真实query类别只用于诊断。
4. 固定两个小探针：只加8维 `onehot(initial预测)-onehot(raw预测)`；以及只用这8维的对照。共8个逻辑回归拟合，另4个原参考重拟合；原16维标准化、事件总权重、BA训练权重、C=.1和阈值=.5固定。没有训练骨干或搜索参数。
5. 见到加性分解后，追加三个明确标注为事后的路径中和：支持计数、支持OOF、两者同时置回源参考均值。不是把支持样本删掉，也不是已验证的部署策略。
6. 独立支线分析同一query在五个支持集下的修正机会及接受判断变化，以及OOF支持证据的稀疏性。

源HELD三个context共享留出船，不是三个独立港；目标为三港各5次、F/OSS2各legacy和new两组各5次。new是此前冻结的另一组支持抽样，不是本轮新采集。上游历史研发暴露继续保留。

## 1. 选择器究竟怎么错退

接受initial的条件是logit>0。以下为被错退的真实救回事件，在各draw内平均后再汇总的加性分数；相对于源标准化参考，不能解释成物理因素的因果百分比。

| 分数组成 | 桑托斯散货 | 洛杉矶原油 |
| --- | ---: | ---: |
| 截距 | +0.503 | +0.405 |
| 置信度相关 | -0.072 | -0.184 |
| 基础分支一致性 | -0.017 | +0.031 |
| 支持OOF | -0.210 | -0.451 |
| 角色支持数量 | -0.520 | -0.262 |
| 支持覆盖/总体统计 | -0.043 | -0.001 |
| 合计 | **-0.359** | **-0.462** |

在桑托斯模型中，initial预测类别支持占比的标准化系数为-0.168，raw类别支持占比为+0.043。也就是说，在其他输入固定时，initial所指类别支持越多，接受分数反而越低。这是源事件数据中拟合出的条件关联，不代表“支持样本多客观上就更差”。保留下来的桑托斯散货救回也有较大计数惩罚，但置信度项均值+0.299能帮助越过阈值。

冻结模型的支持统计并未直接看当前query与哪艘支持船相似。它主要知道该预测类别的总数量、类级OOF救回/误伤及分数。这是当前设计的信息粒度，不等于原完整模型没有使用样本相似度。

## 2. 中和路径后，错误回退真的减少了吗

是，但有代价。下表是相对原BA选择器的全港变化；“找回”严格指同一批原先被选择器丢弃、而initial分对的样本，不是另一些新纠正。数量为五次支持抽样均值。

| 范围/计算干预 | 找回原丢失救回 | 全港OA变化 | 全港BA变化 |
| --- | ---: | ---: | ---: |
| 桑托斯散货：中和计数 | 42.0 / 原丢54.8 | +2.314点 | -0.355点 |
| 桑托斯散货：中和OOF | 12.8 / 原丢54.8 | +0.663点 | -0.070点 |
| 桑托斯散货：两者中和 | 51.6 / 原丢54.8 | +2.962点 | -0.516点 |
| 洛杉矶原油：两者中和 | 4.8 / 原丢5.6 | +1.195点 | -0.387点 |

“找回数量”只统计表中指定类别，而OA/BA列是全港，分母不同。干预也可能新增其他救回或误伤，不能用这一列数量单独推算全港净收益。

全三港中和计数后，OA相对原选择器+0.791点、BA -0.185点；中和OOF为OA +0.441、BA -0.152点。巴生原有BA +0.630点收益会分别缩到+0.536或+0.341点。因此不能把支持统计统称为噪声然后全部删除。

源HELD中和计数/OOF相对原选择器的BA分别+0.065/+0.125点，但目标三港不保留这个方向。这是现有支持统计作用范围改变的证据之一，不是仅调一个全局强度就一定可以迁移。

### 为什么数量惩罚在BA下并不反常

将所有query按“initial预测类别支持数是否多于raw预测类别”划为两组，阈值就是0差值，没有搜索。先用完整query计算OA或BA权重，再统计其中一对一错的事件，各任务权重等量平均。下面关注支持数增加组，比例仅在救回/误伤事件间计算；源任务大小不同，micro也不是直接汇总事件数之比。

| 范围 | 按样本数的救回占比 | 按BA权重的救回占比 | 该组initial相对raw的OA贡献 | BA贡献 |
| --- | ---: | ---: | ---: | ---: |
| 桑托斯context源FIT | 65.90% | 45.26% | +1.491点 | -0.374点 |
| 桑托斯目标港 | 77.06% | 40.51% | +3.581点 | -0.707点 |
| 洛杉矶目标港 | 71.08% | 49.91% | +2.201点 | -0.007点 |
| 巴生目标港 | 51.83% | 42.08% | +0.173点 | -0.485点 |

也就是说，支持数增加组中，救回的样本更多，但受到误伤的类别在BA下权重更高。针对这一组降低接受倾向，可能牺牲很多张图而提高BA。这与前轮只改训练权重的实验、中和计数后OA恢复但BA下降的结果相互吻合。它说明有实际目标取舍，不应把计数项直接叫作“纯噪声”“实现错误”或“已证明无法迁移的伪相关”。

这一表仍是条件组的平均规律，不保证每个样本或每个支持抽样都符合。改善的空间在于组内更细的判别，不能靠对整个组作相反的一刀切。明细为 `support_frequency_role_units.csv`、`support_frequency_role_summary.csv`。

## 3. 是否只是没见过这种改判

不完全是。源事件稀疏与其方向偏差是实际问题，但不能把所有损失归于“未覆盖”。

- 桑托斯 `tug_towing -> bulk_carrier` 在源对应context只有3个不同事件观测，按原BA权重的救回比例5.05%；目标每次抽样却平均有22.6个有效救回，其中19.8被丢。这里存在稀疏且方向不同的监督。
- `general_cargo -> bulk_carrier` 源已有40个事件观测，源救回权重比例47.27%；目标仍平均丢15.8个救回。覆盖了预测对，不代表学到了目标上的正确用法。
- `crude_oil_tanker -> bulk_carrier` 源有24个事件观测且这些事件全为救回，目标仍平均丢4.8个救回。仅按预测对的平均好坏不能解释所有回退，角色支持统计与置信度仍在参与。
- 洛杉矶 `product_chemical_tanker -> crude_oil_tanker` 源只有5个事件观测，救回权重比例80.49%；目标平均丢3.2个救回。即使源总体倾向该方向，具体样本仍可能被别的输入项否决。

这些比例是在源任务完整query类别权重下统计的事件条件比例，不是目标识别准确率。目标真实类别只用于分解收益，不能在部署时按真实类挑政策。详见 `source_transitions.csv`、`transition_summary.csv`。

## 4. 补上类别身份是否有效

| 范围 | 旧选择器OA / BA | 加类别方向OA / BA |
| --- | ---: | ---: |
| 源HELD | -1.090 / +0.341 | -1.090 / +0.287 |
| 三港平均 | -1.400 / +0.267 | -1.408 / +0.278 |
| F_0921 legacy | -0.142 / +0.276 | -0.367 / +0.118 |
| F_0921 new | -0.265 / +0.144 | -0.377 / +0.020 |
| OSS2 legacy | -0.052 / +0.418 | -0.424 / +0.281 |
| OSS2 new | +0.047 / +0.321 | -0.041 / +0.309 |

有局部保留价值但没有形成明显增量：桑托斯BA从+0.376变成+0.478点，OA仍-3.021；巴生仍OA +0.244/BA +0.579，BA5/5为正，但旧版本更高。只用类别方向的对照三港OA -0.013/BA +0.040，不能复现支持证据的主要BA收益。

强基线也保留：新探针在OSS2 new比简单置信度低OA 1.221、BA 0.169点；在Fnew比旧combined低OA 0.575、BA仅高0.010点。不能只因比initial某项均值为正就宣布新模块成功，也不以某一港退化否定已有的巴生正信号。

详细绝对OA/BA在 `summary.csv`、`summary_task.csv`；配对比较在 `comparison_summary.csv`；支持抽样变化在 `variation.csv`。

## 5. 同一张图与支持集：机会变化还是选择器变化

两者必须区分。桑托斯散货744个query中，262个观测至少出现一次有效救回，但没有任何观测五次都被initial救回；其中只有16个观测/16艘船在多次有效救回之间既被接受、又被回退，217个观测的所有已有救回机会都被丢弃。因此，上轮“没有样本五次都被错退”不能单独推出选择器判断不稳定，很多样本根本没有五次救回机会。

在可作同图救回配对的16艘桑托斯船上，接受时initial类别支持数均值6.66，回退时8.34，而initial概率margin几乎相同（0.02935/0.02994）；OOF和raw分数也同时变化。这与支持计数惩罚的计算路径一致，但不是隔离所有其他变化的随机干预。洛杉矶原油只有5艘船可作这种配对，不能当作大样本结论。

支持交叉验证的有效信息很稀疏：每组16个案例，洛杉矶/桑托斯平均只有0.6/0.8个非零修正事件，分别3/5、2/5组完全没有事件。桑托斯被错退救回中的71.53%，对应initial类别没有OOF正事件；但保留下来的救回也有65.22%没有，不能拿“没有正事件”直接当回退或保护条件。洛杉矶这两组更是都100%没有OOF正事件。

这说明缺少的是可靠且与当前样本有关的效用证据，不能把“少量支持验证没有观察到收益”写成“这个修正没有用”。OOF稀疏是信息限制，不是已被证明的唯一失效根因。

## 6. 现在更值得做什么

本轮不再扩展类别编码或调门控阈值。更有针对性的下一步是检查：**当前待测样本的改判，是否得到具体支持案例的判别证据支持，而不只是落入“这个类别的支持数量/平均OOF表现”这一类级统计。**

应先用已有缓存作源留出可行性分析，把样本与支持案例的关系作为候选证据，检查能否在保留巴生等有效拦截的同时减少错误回退。必须先建立可用信号，不能从本轮离线确认的42张可恢复救回直接跳到“新机制一定能将它们与误伤区分”。这些是下一步方向，本轮未启动邻域模块训练。

支持交互支线的实际同图配对结果、OOF事件分母和限制另见 `SUPPORT_FINDINGS_ZH.md`，不把它与加性logit干预混成物理因果。

本轮还修复一处实际汇总错误：旧condition逐样本分组漏掉缺失MMSI的行，Santos至少一次丢失救回应为233观测/201已知船，非232。对旧脚本增加保留空键和观测总数检查，重算后累计274次丢失、每draw54.8及所有OA/BA不变。原报告保留更正说明，不修改任何冻结预测。

## 复现与边界

`run_probe.py`负责固定训练/预测/评价；`diagnose.py`负责源事件覆盖与logit分解；`neutralize.py`负责事后冻结路径中和。主线8个新小拟合+4参考重拟合，0个新骨干训练；44评价单元，历史开发集，不声称新增独立数据。

880个原指标重放、656个OA/BA逐类求和检查通过，原参考重拟合误差<=2.23e-16，诊断44个事件账目加回原BA。路径中和重新核对44个原始端点。完整验证范围见 `AUDIT_ZH.md`。
