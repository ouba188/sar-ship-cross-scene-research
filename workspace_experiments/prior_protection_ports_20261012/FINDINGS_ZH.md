# 23港扩展：逐类约束的收益、代价与失效原因

日期：2026-10-12。345个正式单元完成，无新神经训练，主模型未替换。

## 结论先说

**这条路线有真实的OA收益，但外部两数据集上的OA/BA双提升没有原样扩展到23港。** 数量规则在64、128例时分别有20、18个港口平均OA提升，但BA分别只有8、6个港口提升。不能概括成全面成功，也不能据此否定已成立的F_0921局部收益。

进一步的缓存分数拆分定位到一个具体设计问题：**“案例少，所以应该更强地保留源先验”不是可靠的一般规则。** 128例时，仅施加少支持类别的加强约束，已造成BA约0.943个百分点退化；相反，仅放宽多支持类别的约束可提高OA约2.149个百分点，BA仍下降0.188个百分点。收益与代价可以在计算路径上区分，不能都归因于抽样噪声。

## 1. 范围与口径

- 自建24港体系中已有23个可评价港口；沿用既有排除Melbourne的队列，不新增选择。
- 支持预算16、64、128，每档五组既有抽样，共345个单元。与旧模型使用相同支持、共同查询、逐港源模型和特征处理。
- 正式候选在全部预测冻结后统一评价。原规则参数未调整，没有按目标港选择最佳方法。
- 先平均每港五组抽样，再对23港等权。每港BA只平均该查询集中实际出现的类别，输出空间仍为8类；实际查询类别数有3、4、6、7、8类。
- 预测时不输入查询标签，也不告知模型本港实际出现哪些类别。实际类别数仅用于评价及事后分析。
- 历史支持/查询是行级排除，不是严格未见船验证；五组支持抽样不是五个训练种子，23港也不是全新独立确认数据。

## 2. 正式完整模型结果

OA、BA为百分数，差值为百分点，五抽样后逐港等权均值。

| 支持数 | 原OA | 数量规则OA | ΔOA | 原BA | 数量规则BA | ΔBA | OA提升港数 | BA提升港数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 16 | 64.930 | 65.372 | +0.442 | 49.091 | 49.213 | +0.122 | 13/23 | 11/23 |
| 64 | 64.677 | 66.548 | +1.871 | 55.855 | 55.807 | -0.048 | 20/23 | 8/23 |
| 128 | 63.837 | 65.201 | +1.364 | 57.634 | 56.538 | -1.096 | 18/23 | 6/23 |

宏Brier风险分别增加0.000542、0.001135、0.001423，均为变差。不能只突出OA，忽略类别均衡性和概率风险。

115个配对抽样单元中，64例有83个OA正向、47个BA正向；128例有82个OA正向、37个BA正向。这些重复查询的单元不是115个独立实验。

以港口重采样得到的BA差描述性95%区间：16例[-0.256,+0.654]，64例[-0.503,+0.541]，128例[-2.600,-0.072]。它描述该历史队列的港间离散性，不是新采集数据上的泛化保证。

### 小查询港口的影响

Mombasa共同查询只有7例，128例时BA差为-15个百分点，放大了平均损失。协议预先规定另报查询数至少30的敏感性，得到22港：

| 支持数 | ΔOA | ΔBA | Δ宏Brier |
| --- | ---: | ---: | ---: |
| 16 | +0.332 | -0.100 | +0.000761 |
| 64 | +1.827 | -0.277 | +0.001689 |
| 128 | +1.816 | -0.464 | +0.002247 |

因此，小港确实放大128例的BA损失，但**不能解释全部退化**。主结果仍保留23港，不删除不利样本。

| 数量规则 | +0.442 / +0.122 | +1.871 / -0.048 | +1.364 / -1.096 |
| 同平均正则统一约束 | +0.054 / +0.687 | -1.176 / -0.026 | -2.681 / -1.644 |
| 仅缺席类保护 | +0.099 / +0.661 | -0.212 / +0.096 | -0.528 / -0.202 |
| 源置信度约束 | +0.155 / +0.709 | -0.135 / +0.168 | -0.569 / -0.309 |
| 已有关系修正 | -0.354 / -0.612 | +0.084 / +0.001 | -0.020 / -0.049 |
| 关系修正+缺席类保护 | -0.331 / +0.147 | -0.171 / +0.087 | -0.580 / -0.240 |
| 旧固定缩放 | -0.358 / +2.068 | 0 / 0 | 0 / 0 |

逐类分配仍比统一正则更有利于OA，但这不等于比原模型更有利于BA。16例的简单缩放有更高BA、同时损失OA，也不是无代价胜出。不能根据这张表事后拼出逐预算最佳组合，然后当作已验证算法。

## 4. 为什么OA和BA走向不同

先按支持数量，把本港实际出现的查询类别分为零支持、低于B/8、至少B/8三组。下表为各组对完整BA变化的贡献，三项相加等于正式数量规则的总变化：

| 支持数 | 零支持类 | 少支持类 | 多支持类 | 总BA差 |
| --- | ---: | ---: | ---: | ---: |
| 16 | +0.657 | -0.283 | -0.252 | +0.122 |
| 64 | +0.312 | -0.750 | +0.390 | -0.048 |
| 128 | -0.001 | -1.248 | +0.154 | -1.096 |

这是损失发生位置，不单独证明是哪条更新路径导致它。原始分组和修复/误伤数在`support_groups.csv`。

类别分析与这一现象一致。128例时，散货船、成品油/化学品船平均召回变化约+1.997、+1.765个百分点；集装箱船、拖轮、海工补给船约-4.109、-2.200、-2.283个百分点。各类别召回是在有该类的港口平均；全局BA贡献另按每港实际类别数和23港权重计算，不能直接将这些召回变化统一除8。

样本较多类别更好，足以抬升按样本计数的OA；多个少数类别退化，则会抵消或压低类别等权的BA。这是本轮OA/BA分离的直接统计解释，不涉及猜测物理机制。

## 5. 更进一步：拆开更新路径

以下是**看到正式结果后开展的机制诊断，不是预先冻结的新主方案**。只替换已缓存专家分数的对应类别列，不重新训练、不重新拟合，不按查询标签挑选列：

- `count_high_only`：仅保留支持数至少B/8的类别更新变化，其余列恢复原模型。
- `count_low_only`：仅保留支持数介于0与B/8之间的类别更新变化，其余列恢复原模型。
- `guard`：仅保留零支持类的分数保护，已有正式对照。
- `count_supported_only`：保留全部有支持类的数量约束，零支持类恢复原模型。

三组列变化在专家原始分数层严格重建完整数量规则。softmax与argmax是非线性的，**不能把下面各项准确率差直接相加或当作因果贡献百分比**。

| 诊断路径 | 16例 ΔOA / ΔBA | 64例 ΔOA / ΔBA | 128例 ΔOA / ΔBA |
| --- | ---: | ---: | ---: |
| 仅放宽多支持类 | +0.304 / -0.525 | +1.874 / -0.387 | +2.149 / -0.188 |
| 仅加强少支持类约束 | +0.018 / +0.080 | +0.008 / +0.065 | -0.578 / -0.943 |
| 有支持类数量约束，去掉零支持保护 | +0.306 / -0.443 | +2.012 / -0.259 | +1.710 / -0.992 |

由此能说清三件事：

1. **128例的主要问题确实与少支持类别路径有关。** 仅这条路径已造成明显损失；去掉零支持保护后BA仍下降约0.992，不能只怪零支持处理。Mombasa贡献了部分损失，但剔除小查询港后的正式BA仍下降。
2. **多支持类适配是可利用的OA收益来源，但也会引起类别竞争。** 单独改变这些类别的分数，64/128例OA明显提高，BA仍略降；因此仅停止加强少支持类约束，也尚未解决全部权衡。
3. **缺席类保护对概率风险另有影响。** 去掉它后，64/128例宏Brier差变成-0.003071/-0.003680，即风险改善，但BA仍下降。它不是整个失效的唯一原因。

本港查询中从未出现的类别，其预测占比在128例从原模型0.855%增至数量规则1.250%；这说明保护可能保留了部分不合适的竞争分数。但“在查询中缺席”不等于该港现实中永不存在，且模型不知道查询类别集合，不能用查询标签将这些类直接屏蔽。

这些计算路径干预比只看总体指标更接近机制证据：**在本模型内，改变什么导致哪种结果可以定位。** 但它们没有识别独立物理因果因素，也不保证所有港口的个案原因相同。

## 6. 有没有值得保留的范围

有。外部F_0921的64/128例OA、BA均提升，五组BA全为正，原结果继续成立。此次23港中的Newcastle同样有明确局部正信号：

| 预算 | OA增量 | BA增量 | BA正向抽样 | 查询数 |
| --- | ---: | ---: | ---: | ---: |
| 64 | +9.213 | +1.810 | 5/5 | 89 |
| 128 | +8.539 | +3.286 | 5/5 | 89 |

这属于同一小查询队列上的重复支持抽样，不能扩写成独立确认。Santos、Singapore等也有OA/BA均值正向，但抽样并非全胜。逐港数值完整保留在附表。

所以当前判断是：**按类分配适配强度值得保留，但“用支持数量倒数作为可靠性”还不够好。** 研究应区分三件事：样本数量、源先验是否适合该类、该类更新是否会压过其他类；它们不是同一个量。

## 7. 下一步建议，不在本轮自动执行

不再为数量规则增加复杂网络。先针对明确问题做一个小范围可利用性测试：能否仅用源端留出任务或支持集内部的分组验证，判断某类源先验需要保留还是需要纠正，再约束对其他类的误伤。

已有普通支持CV在历史任务上并非稳定获益，不能把再做一次CV说成新意。新检验必须具体回答：**是否能识别本轮测出的逐类有害更新，而不是仅估计一个整体最优缩放？** 先证明可预测性和净收益空间，再开发模块；若证据不足，保留已验证任务范围，不硬做通用门控。

高支持类单独放宽的路径可以作为已发现的候选边界，但它在23港BA仍略降，并且未扩展到F/OSS2，不能直接升级为新的全局主模型。
