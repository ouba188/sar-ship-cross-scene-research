# 能否预判关系校正的净收益：有源域信号，尚未转化为跨港增量

2026-10-13。本轮已完成。结论：**不把当前学习选择器加入主方案。原有关系校正的收益保留；简单分数选择在源域未见船上有正信号，但跨港增量没有成立，加入支持可靠性信息反而削弱泛化。** 这是这个固定小样本配方的结论，不是证明所有自适应选择都无效。

## 1. 本轮实际做了什么

- 固定B16、关系校正dose=1，二选一：raw完整概率融合，或initial完整概率融合。不是基础分支/专家二选一，也不节省骨干计算。
- 8维score_only：两方案的最大概率、前二间隔、概率差异、与基础分支的一致性；16维contextual另加支持OOF净效用、不确定性代理和覆盖信息。
- 两种均为L2逻辑回归，C=.1、阈值=.5，参数事先冻结，无网格搜索。训练目标直接区分救回(+1)与误伤(-1)，不是Brier门控；中性事件不提供相对优劣监督。全query类别权重在筛事件前计算，正负事件不另行平衡。
- 3个港使用各自对应context的9个源FIT episode训练，external使用pooled27个，共8个小模型。每个context的上游头/几何排除了自己的目标港；不能把别的context合并后仍声称严格逐港排除。
- 源FIT共2178次预测暴露，242个不同query、103艘船。有效事件219次，来自91个观测、60艘船，不是219个独立样本。
- 支持OOF为3次4折，raw/initial/base均按内折重算，initial只变换训练支持，验证保持raw。先平均同一支持行3次概率，不把16个标注算作48个。各类救回/误伤/中性用Dirichlet(1,1,2)平滑；其标准差是工作模型下的代理，不是已校准的真实收益置信区间。
- 27个FIT、9个源HELD、15个历史目标港、20个外部单元，共71个单元的选择结果先冻结，再评价。没有新增骨干、源头或关系映射训练，没有改变旧结果。

## 3. 原因定位：哪里有信号，哪里失效

### 3.1 不是完全没有可学习信息

仅在一对方案中一对一错的事件上，按全query类别分母计算加权AUC：

| 范围 | score_only AUC | contextual AUC |
|---|---:|---:|
| 源FIT | 0.672 | 0.785 |
| 源HELD未见船 | **0.652** | 0.490 |
| 三个目标港 | 0.544 | 0.487 |
| F前轮new | 0.518 | 0.491 |
| OSS2前轮new | 0.489 | 0.478 |

同context的分数选择从FIT到源HELD保留排序信号，并有最终收益；再到目标港明显减弱。外部采用pooled模型，不能把其与context专用模型的AUC差全部当成纯数据域效应。AUC只衡量事件间排序，不是准确预测每张图能否修正，也不自动保证优于全initial。

### 3.2 当前支持可靠性画像太稀疏，学到的关系不稳定

每16个支持案例中，在重复OOF概率平均后，真正出现raw/initial一对一错的行平均只有：洛杉矶0.6、巴生港1.4、桑托斯0.8、F-new1.4、OSS2-new1.2。还要分到8个类别，许多类别没有有效相对效用事件。

替换对照显示：加上这8维支持信息，FIT比score_only更好，但源HELD平均BA反而低0.830个百分点、三港低0.636。与训练拟合过度及支持画像迁移不稳一致。

一个明确的关系反转例子是“initial预测类别的支持占比”：其事件AUC从FIT的0.644变为源HELD的0.342；对应的支持不确定性代理从0.322变为0.664。画像并非提供了普遍稳定的“越多支持越可信”规律。这里的单变量分析是事后解释，不用于新阈值或特征筛选。

**已证实的是当前输入组合没有稳定泛化、支持相对效用证据稀疏、部分相关方向反转。尚不能唯一归因为标注少：训练episode多港混合与目标单港适配的组成差异、支持内折12个左右与完整16个的读出差异、有限模型形式等仍可能参与。** 没有通过增加模块掩盖这些未区分解释。

### 3.3 净收益为什么消失：挡住误伤，也丢掉更多救回

相对initial，选择器增量恰好为“避免的误伤BA - 丢失的救回BA”：

| 范围/方案 | 避免误伤 | 丢失救回 | 净增量 |
|---|---:|---:|---:|
| 源HELD score_only | 1.011 | 0.530 | +0.481 |
| 三港 score_only | 0.685 | 0.987 | -0.303 |
| 三港 contextual | 1.022 | 1.961 | -0.939 |
| F-new contextual | 0.690 | 0.727 | -0.037 |
| OSS2-new contextual | 1.498 | 1.671 | -0.173 |

这说明确实有错误被避免，并非选择器完全不工作；问题是它没有稳定保住更有价值的修正。目标事件排序接近0.5，不能把未收益简单说成“再调一个阈值就能解决”。原raw/initial对有oracle空间，但本轮没有证明可用信息足以兑现跨港空间。

## 4. 身份、范围与成本

- source HELD的9个单元共用418个query、156艘船、20个真实港口，FIT与HELD船身份分离；实际港口分层在source_held_actual_ports.csv。不能把3个几何版本说成3个独立目标港。
- 三个历史目标港沿用B16支持/query行级划分，存在同船不同观测。各context的目标港/船/产品源排除成立，但没有重新交叉拟合全部骨干/分频表征，不称全链路未见船确认。
- 外部pooled训练与源FIT有身份重合。预先固定排除全部FIT已知船的query后，F保留122290/123170行，OSS2保留3434/3440行，保留行未知身份数均0。new组contextual相对initial BA仍为F-0.034、OSS2-0.179；主要结论不因这部分重合改变。多context上游暴露边界仍保留，不升级成严格独立确认。
- 8次小模型拟合共0.627秒；两个选择器及置信度一起处理F的123170个query平均约47-64ms、OSS2的3440个query约1.2ms，均不含特征构造、支持OOF、骨干提取、加载与写出。
- 新算三港每支持组的paired OOF核心平均22.1ms，不含kernel准备、分折等；外部复用已有OOF。源输入准备3.58秒、目标输入准备39.50秒含缓存处理，不是部署时延。

## 5. 验证与决策

三项针对性单测通过：净效用方向/完整类别权重、重复OOF不增加标注、角色特征类别重排不变及学习方向。36个source raw读出重放最大误差8.53e-15，FIT initial同样逐单元重放通过；15个目标港单元的两种读出首32query重放最大误差9.11e-15。未发现能解释退化的接入/索引/融合错误。独立有界审阅结果另记AUDIT_ZH.md。

**本轮收口：保留关系校正及源域score_only的正信号，不推广contextual作为跨港创新模块，不按目标结果选择不同策略，也不追加C/阈值搜索。** 先前“前人做到了统计选择”的文献依据没有错，但不等于本任务的B16支持画像已经足以可靠选择。

后续若继续这条路线，最有辨别力的问题是：在更贴近真实部署的源单港episode中，原有分数/支持证据能否产生可迁移净效用。那属于新一轮可行性检验，不是本轮已完成或已启动工作。现有主模型与论文均未替换。
